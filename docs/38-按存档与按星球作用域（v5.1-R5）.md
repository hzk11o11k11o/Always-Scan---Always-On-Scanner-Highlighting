# 38 · 「未扫描的星球资源显示绿色」——记忆必须按**存档**（读档边界）与按**星球**（worldspace）作用域
（DLL v5.1.0 订正 R5 / 公开版仍 `2.0`）

> 建立：2026-09-27（深夜，接 `docs/37`）。
> 触发：用户报告（原文）——
>
> ```
> 未扫描星球资源直接显示绿色问题还存在，特别是重新读档后（未扫描时的存档）问题非常严重
> ```
>
> 承接：`docs/33`（v5.1：记忆粒度 base → 引用）、`docs/35`（v5.1.2：按物种扩散）。
> **一句话结论**：「已扫描」是**存档里勘测数据**的事实（引擎判据函数 `0x1597A50` 查的就是
> 当前存档的数据），而 MOD 的记忆有**两层**都不分存档、且其中一层还不分星球：
> ① 按引用记忆（含落盘文件 `SAS_AlwaysScan.flora-learn.txt`）**跨存档**有效；
> ② v5.1.2 的「按物种（base）扩散表」是**全局**的（只按 base 记）⇒ 在星球 A 学到的物种
> 会让星球 B 上**同种但没扫过**的资源也变绿（= docs/33 里 base 级记忆那个坑的翻版）。
> 治法 = 给两层记忆各加一个作用域：**读档 = 存档边界**（引擎 `TESLoadGameEvent`）+
> **按物种扩散只在同一颗星球（worldspace）内生效**，并在每次读档用**资源链**当场复核、
> 把「本存档里必然没扫描」的条目丢掉。

### 1.4 v5.1.2 的扩散表为什么也脱不了干系（跨星球）

`docs/33` 已经定性过一次：**base 级**记忆会让「同 species / 同资源的所有实例，**含跨星球**」
一起变绿 —— 那正是用户当时报的「矿石、植物扫描前后颜色都是绿色」。
v5.1 把**引用级记忆**收窄到引用，但 v5.1.2 又新增了一张 **base 级**的会话表
（本意是补「引擎没画到的实例」），而它**只按 base 记、不分星球** ⇒
在同一会话里从星球 A 飞到星球 B 时，A 上确认过的物种会让 B 上**没扫过**的同种资源变绿。
⇒ 扩散必须带上「见证时所在的星球」。

**行为变化（给用户的三句话）**：

1. **读档后不再有「上一个存档学到的绿」**：本会话第一次读档仍信任落盘记忆
   （重开游戏继续玩同一个存档 = 扫过的目标不用再开一遍扫描仪）；**之后**每次读档
   只认「这个存档里当场见证过」的绿，并用资源链把**能证明**「本存档里没扫描」的矿脉 /
   气泉 / 液池条目当场删掉；
2. **同一颗星球**内：已扫描的物种仍然整片变绿（v5.1.2 的修复保留）；
   **换星球**之后：只有**那颗星球上真的扫过**的才绿（不再跨星球外溢）；
3. 代价（如实说明）：读档后**已扫描的植物**在「先举一次扫描仪」之前会显示成
   未扫描的青色（引擎那时才会把 4/5 画出来让我们学到）；矿脉 / 气泉 / 液池不受影响
   （资源链当场就能给出正确答案）。

## 四、验收判据（下一次进游戏）

1. 启动日志（逐行核对）：
   ```
   SAS_AlwaysScan v5.1.0 loading（订正 R5：读档作用域 + 星球作用域 —— 记忆按存档隔离 + 扩散限同星球 + 资源链复核）
   load event: 读档事件 sink 已注册（源 0x…，sinks size=N cap=…）
   config: floraSpeciesPlanetScope=1 -> 按物种（base）扩散**只在同一颗星球**内（…）
   config: floraMemoryScope=1 -> 「已扫描」记忆按存档隔离（…）
   flora learn: 按引用记忆已从落盘文件载入 N 条（…）
   ```
   ★ 若出现 `load event: 读档事件源拿不到 / 形状不像 BSTEventSource` ⇒ **把那一行发出来**
   （此时「按存档隔离」会退化，假绿可能回来）。
2. ★★ **读档场景（本次修复的核心）**：先玩到扫过一些资源，**再读回一个更早的存档**
   （那次存档里没扫过）⇒ 走一圈看：
   * 那个存档里**没扫过**的矿脉 / 植物 ⇒ **青色**（不再绿）；
   * 同一颗星球上那个存档里**确实扫过**的 ⇒ 矿脉立刻绿（资源链当场判）、
     植物在你**举一次扫描仪**之后绿（引擎画 4/5 ⇒ 被我们学到）；
   * 统计行 `读档=` 在涨；`跳过=` / `链复核: 丢=` 出现非 0（= 过期记忆真的被挡住 / 删掉了）。
3. ★★ **换星球场景**：在同一会话里从星球 A 飞到星球 B ⇒
   B 上**同 species 但没扫过**的资源必须是**青色**；
   统计行 `按物种扩散 … 星球外拒=` 出现非 0。
4. ★ **重开游戏继续玩同一个存档**：本会话第一次读档后，之前扫过的目标
   （落盘记忆）应仍然直接是绿的 —— 这条**不能回归**（docs/33 验收 ⑤）。
5. 不回归：F8 开关 / 扫描仪自愈 / 展示柜（关着也亮、拿空即灭）/ 换场景不崩 /
   活人不亮 / 分组配色 / `引擎状态表: 条目=` 稳定 / 动态场景不卡（`timing3` 的 `卡顿` 与
   `最慢一轮 cpu=`）。
6. 回退开关（都不用换 DLL）：
   * `FloraMemoryScope=0` ⇒ 完全回到 v5.1.4 的旧行为（记忆永远有效、物种表不清）；
   * `FloraMemoryScope=2` ⇒ 最严格（落盘记忆一律只当提示，全部要求本存档内见证）；
   * `FloraSpeciesPlanetScope=0` ⇒ 按物种扩散回到「全局」（对照用）。

★ **已知边界（如实记录）**：
* 植物（产出 MISC）**没有**可用的引擎判据（引擎那条链只认 LVLI）⇒
  「读档后到举扫描仪之前」这段时间只能显示青色；矿脉 / 气泉 / 液池不受影响。
* `FloraMemoryScope=1` 的「第一次读档信任落盘记忆」是一条**保守假设**
  （重开游戏后读的通常就是上次那个存档）。若用户「重开游戏 → 直接读一个更早的存档」，
  矿脉 / 气泉 / 液池仍会被资源链纠正，但**植物**可能要等举一次扫描仪；
  要彻底严格就设 `FloraMemoryScope=2`。

## 五、可复用经验（写给下一轮）

1. **「事实」的作用域必须和它的真实作用域一致**：「已扫描」是**存档 + 星球**两级事实
   （引擎自己的判据函数查的是当前存档的勘测数据；物种扩散在引擎里也是随场景 / 星球的），
   而记忆如果只有一个维度（引用 / base），就一定会外溢 —— 这一轮补的正是这两个维度。
2. **同一类 bug 会在不同层重演**：docs/33 修的是「base 级记忆跨星球 / 跨存档」，
   v5.1.2 为了修另一个 bug 又新增了一张 base 级表 —— **新加的记忆层要先把作用域问清楚**。
3. **能用引擎自己的事件当边界，就别用间接信号**：
   「载入画面由开变关」**读档与换场景都会发**（v4.0 起一直这么用），
   而 `TESLoadGameEvent` 只在读档时发 —— 一条事件就把「存档边界」钉死了。
   commonlibsf 里没有现成的头可用时，**本地定义同布局类型 + REL::ID 取源**是这个项目
   已经用了三次的成熟做法（v4.11 菜单事件 / v4.13 两个游戏事件 / 本轮读档事件）。
4. **新增的引擎调用都要先离线核对 ID → RVA → 反汇编**：
   本轮两个新调用（`GetEventSource` / `GetParentWorldSpace`）都先查 versionlib 再反汇编，
   并用**已知常量交叉验证**（`GetOutlineState` = ID 83007 = 0x1306E80 ✓）。
5. **「证伪」比「证实」便宜且可靠**：资源链只能证明「这个资源**不在**本存档的勘测数据里」
