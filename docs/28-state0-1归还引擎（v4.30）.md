# 28 · 「扫描中的 NPC 全部变成赏金色」的真根因：state 0/1 归还引擎（DLL v4.30.0 / 发布版 1.7.8）

> 建立：2026-09-26。触发：用户实测反馈（附截图，NAT 站内 3 个人形：1 红 + 2 品红）——
>
> ```
> 扫描中的NPC全部变成了这种只有带有赏金的人物才会出现的颜色，
> 修正，将NPC扫描还原到原版颜色
> ```
>
> 一句话结论：引擎的逐引用求值函数（`0x159ED90`）对**通用引用（含活人 NPC）**
> 写 **state 0（远）/ 1（近）**，而 v4.19~v4.29 把这两个槽位覆盖成
> 「武器 红 `#FF2E2E` / 服饰 品红 `#FF3BD4`」⇒ 举着扫描仪时**所有行人**跟着变色。
> 修法 = **0/1 一个字节都不写**（与 v4.22 归还 7/8、v4.24 归还 4/5 完全同构）。

---

## 一、证据链（截图取色 + 日志排除 + 反汇编 + 原生色表）

### 1.1 截图逐像素取色（工具 `tools/img_outline_color.py`）

对用户截图（602x612）做色相分桶 + 分块取色：

| 区域 | 最饱和像素 | 色相 | 判定 |
| --- | --- | --- | --- |
| 左侧人形（远） | `#F00D06` / `#F11008` / `#F4250C`（sat≈232） | 1.8° ~ 8.5°（红） | ≈ **MOD 的 state 0 覆盖色 #FF2E2E（0°）** |
| 右侧两人形（近） | 品红像素 `#F8C5EF` / `#F7C9E7`（全图 7 321 px 集中在右侧两列） | 310.6° ~ 320.9°（品红） | ≈ **MOD 的 state 1 覆盖色 #FF3BD4（313°）** |

★ 关键：**11 个槽位的原生色 + MOD 覆盖色里，「红 `#FF2E2E`」与「品红 `#FF3BD4`」
只有 state 0 / 1 有**（4/5 绿、7/8 青、2 蓝、3 紫、6 黄、9 橙、10 白——全部排除）。

### 1.2 日志排除法：MOD 自己从未挂过 0/1

用户那一局（`SAS_AlwaysScan.log`，20:09 与 20:53 两个会话）逐条核对：

* `category (本轮选中): … weapon=0, apparel=0 …` —— **两个会话都是 0**
  （窗口内累计选中 0 次 ⇒ MOD 没挂过任何 state 0/1 目标）；
* `rejTypes` 里能看到 ACHR（ft=0x4B）被拒（`判活跳过 1300+`），
  `candTypes` 只有 MISC/CONT/ARMO/WEAP/AMMO/FLOR（MOD 的候选全是物品）；
* ⇒ 红/品红人形**不是 MOD 挂的**，只能是引擎自己挂的、被 MOD 的**全局颜色覆盖**改了色。

### 1.3 反汇编 `0x159ED90`（引擎扫描仪的逐引用求值函数）

`func.py callers 0x159ED90` ⇒ 唯一调用点 = `0x159EA70 +0x2AF`（遍历 + 调用）。
函数尾部（v4.24 已列）之外，本轮补全 **0/1 与 2/3 分支**（`0x159F5C0`~`0x159F65A`）：

```asm
0159F5CA  cmp cl, 0x3a                  ; cl = 类型（0x3A = kPROJ，抛射物特判）
0159F5CF   …  (cl==0x3A: shr [ref+0x178],6 / and 1)      ; bl = 目标类标志
0159F5DC  call 0x5daca0                 ; 其它类型：formType → bool 查表（0x1D~0x97）
0159F5EE  mov bl, 1 / xor bl, bl        ; ⇒ bl
0159F5F0  mov rcx, [rdi+0xc8]           ; ★ 分支①
0159F5F7  call 0x5129d0
0159F5FF  je 0x159f60c
0159F601  mov edx, 0xa                  ;   [ref+0xC8] 非空 ⇒ state 10
0159F60C  movzx eax, byte [rbp+0xe8]    ; al = 「在范围内」
0159F613  test bl, bl
0159F615  je 0x159f627
0159F619  test al, al / setne dl
0159F61E  add edx, 7                    ; ★ bl != 0 ⇒ 7（远）/ 8（近）
0159F627  mov edx, [rsp+0x28]
0159F62B  cmp edx, 0xc / jne …          ;   原状态 != 12 ⇒ 保持原样
0159F632  test r13b, r13b               ; r13b = 调用者传的「每条目标志」
0159F639  setne dl
0159F63C  add edx, 2                    ; ★ r13b != 0 ⇒ 2（远）/ 3（近）
0159F641  test al, al / setne dl
0159F643  …                             ; ★★ r13b == 0 ⇒ 0（远）/ 1（近）
0159F64F  call 0x17d52b0                ; 写状态（SetOutlineState）
```

★ 结论（本轮的核心事实）：

* **state 0 / 1 = 引擎给「通用引用（含活人 NPC）」画的槽位**；
  `1 = 在范围内（+1）、0 = 不在范围内` ⇒ **远处 = 0、近处 = 1**；
* 触发条件：`bl == 0`（非「目标类」）∧ `原状态 == 12`（还没挂过）
  —— 也就是「第一次看到某个普通引用」（城市里的行人、地面物品……）；
* 与截图**一一对应**：远处的人形 = state 0（红）、近处的两人 = state 1（品红）。

### 1.4 原生色表（用户那一局 `outline colors[install]`，覆盖前原值）

```
state= 0 Generic            基色=#3EADF2 a=00 脉冲High=#3EADF2 a=FF 脉冲Low=#3EADF2 a=80
state= 1 Scanned            基色=#B3C1EF a=00 脉冲High=#72E8FF a=FF 脉冲Low=#115B69 a=FF
```

⇒ **原版行人 = 青（远）/ 亮青（近）的脉冲轮廓**；这就是「还原到原版颜色」的落点
（0/1 不覆盖 = 自动恢复这两个原生值，零改动需求）。

## 三、取舍（如实记录）

| 项 | 旧观感 | 新观感 | 说明 |
| --- | --- | --- | --- |
| 活人 NPC（举着扫描仪） | **红（远）/ 品红（近）**（bug） | **青 / 亮青**（原版） | 用户要求，本轮核心 |
| 武器 / 服饰 | 红 / 品红（state 0/1） | 红 / 品红（state 9/10） | **观感不变**；9/10 的引擎目标很少见（与容器 / 门原先住 9/10 风险同级） |
| 容器 / 尸体 | 橙 `#FF9500`（state 9） | **原版亮青**（state 1，不覆盖） | ★ 代价：搜刮目标仍是「醒目色」，但不是橙色了 |
| 门 | 白 `#FFFFFF`（state 10） | **原版青**（state 0，不覆盖） | ★ 代价：观感仍近「白 / 淡青」 |

* 为什么容器 / 门必须让出 9/10：0/1 归还后「武器 / 服饰」需要新家，
  而 9/10 是**全表里引擎目标最少见**的两个槽位（城市实况：9 = 3 个元素、
  10 = 11 个元素，其余槽位 0/4/7 都是几百）；
* 全部可回退（不用换 DLL）：`StateContainer` / `ColorContainer` /
  `StateDoor` / `ColorDoor` / `StateCorpse` / `ColorCorpse` 都是 INI 键；
  但要恢复「橙容器 / 白门」需要同时接受 9/10 与武器 / 服饰抢槽
  （文档与 INI 注释里都写明了代价）。

## 五、经验（可复用）

1. **「只有 X 才会出现的颜色」是用户给出的高价值线索** —— 它把一个含糊的
   「颜色不对」变成了排除法的输入（色相 → 槽位一一排除）；
2. **颜色覆盖是全局的**：改一个槽位的颜色 = 改「所有使用该槽位的东西」——
   覆盖前必须先回答「**引擎会给哪些东西写这个槽位**」。
   本轮把这句话变成了可执行清单（哪个槽位、引擎的写入条件、实况元素数）；
3. **槽位账本**（本轮建立）：0/1 = 通用（NPC）/ 2/3 = 完全扫描 / 4/5 = 已扫描目标 /
   6 = 引擎从不写 / 7/8 = 未扫描目标 / 9、10 = 罕见（条件未知）。
   **只有 6 是安全的**；其余槽位都在「借」，借之前先看实况占用；
4. **「MOD 没挂过」也要有硬证据**：`category` 计数为 0 + `rejTypes` 里 ACHR 被拒
   —— 两条一起才是完整的排除（否则「MOD 挂的」永远是嫌疑对象）；
5. 修法与 v4.22（归还 7/8）、v4.24（归还 4/5）**同构**：发现「引擎在画的东西」
   被覆盖 ⇒ 归还 + 把 MOD 的类别搬去低风险槽位 —— 这已经是本项目的标准手术。
