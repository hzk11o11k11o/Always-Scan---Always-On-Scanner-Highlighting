## 二、根因（v4.3 采纳判据的三个设计缺陷）

```
旧判据（v4.3 起，2026-09-28 引入轮转采样后彻底暴露）：
     votes[c] >= 3  &&  strong[c] >= 1  &&  bad[c] <= 2        // bad 是「跨轮累计、永不重置」
```

1. **`bad` 是累计硬闸门，而采样是轮转的** —— 2026-09-28 把采样从「每轮都取数组头那 4 个引用」
   改成「轮转扫遍整个场景」之后，样本池从「固定 4 个」变成「场景里所有 CONT / ACHR」。
   ⇒ 只要场景里有**几个**读不出清单的引用，`bad` 就会单调涨过 2 ⇒ **该候选此后永远不可能被采纳**
   （哪怕已有 79 个强样本）—— 本局就是这个形态（`bad=42`）。
2. **「指针为 null」被错当成反证** —— `+0xA0 == 0` 的语义是「这个引用没有库存清单」
   （`RefLootState` 对 `ptrRaw == 0` 就是这么处理的：默认判「空」，`TreatNullInvAsEmpty=1`）。
   它**不能**用来否证偏移，却和「形状自相矛盾」一起被计进 `bad`。
3. **判据是「绝对票数」，没有在同一引用上比较两个候选** —— 真正有区分度的信号是
   「同一个引用上：+0xA0 读出一份带合法物品的清单，而 +0xA8 读不出」；
   只看绝对票数时，「读不出来的引用」和「读得出但形状坏的引用」会互相污染。

★ 时间线（同一现象第三次）：v4.2（一次性 6 样本 + 永久降级）→ 2026-09-28（只采数组头 4 个）→
2026-10-03（`bad` 累计闸门）。三次的表现完全一样：**标定沉默 ⇒ 判空整段跳过 ⇒ 容器 / 尸体不熄灭**。

## 三、修法（只改 `plugin/src/AlwaysScan.cpp` 的标定段 + `main.cpp` 加载行 + INI 注释）

### 3.1 候选偏移分档器（新增，`ProbeInvCandidate`）

每个样本、每个候选分档（只读、零副作用，全部走 `SafeReadMem` / `IsReadable`）：

| 分档 | 判据 | 语义 |
| --- | --- | --- |
| `kNull` | `+off` 是 0 / 那 8 字节读不出来 | **中性**（没有库存清单 = 合法状态，不能否证偏移） |
| `kUnreadable` | 指针看着像但内存读不到（换场景 / 引用刚释放） | **中性** |
| `kShapeBad` | 读到数组头但自相矛盾（size>cap / cap 过大 / data 不可读 / 第一条目 object 不是合法表单） | 反证（只进日志 + 参与同引用对比） |
| `kEmpty` | 形状自洽、条目数 0 | 弱票（只进日志） |
| `kStrong` | 形状自洽 + 第一条目 `object` 是合法 TESForm（`IsPlausibleFormPtr`） | **强证据**（唯一能构成胜场的东西） |

### 3.2 判据（同引用对比 + 反证闸门）

```
每个样本：st0 = 分档(ref + 0xA0)，st1 = 分档(ref + 0xA8)      // 同一个引用上比
  · st_c == kStrong && st_other != kStrong   ⇒ wins[c]++（并记「不同引用数」，饱和到 2）
  · st_other == kStrong && st_c != kStrong   ⇒ loss[c]++（反证）
  · 两个都 kStrong                            ⇒ ambiguous[c]++（只记录，不作证据）
  · 其余（null / 读不到 / 形状坏 / 空）        ⇒ 只计数进日志，**不作为闸门**

采纳：wins[c] >= 3（只有 1 个引用给过胜场时 >= **8**）&& loss[c] <= 2
```

- 「同一引用上不可能同时存在两份合法物品清单」是这套判据的物理依据；
- 「只有玩家自己给过胜场」时门槛抬到 8：单个引用重复采样只能证明「这个引用上对」，
  多等几轮换一个真实容器来交叉确认（本局玩家每轮都给一个强样本 ⇒ 约 8 轮 / 1.6 秒内稳过）；
- ★ 安全底线不变：**胜场只认强证据**，反证（另一候选拿到强证据）≤ 2；
  标定没成功 ⇒ 一律返回「未知」⇒ 不判空（绝不让没验证的偏移进热路径）。

### 3.3 兜底：新 INI 键 `InventoryListOffset`

```
[General]
InventoryListOffset=0        ; 0 = 自动标定（默认）
                             ; 0xA0 / 0xA8（也接受十进制 160 / 168）= 手动指定、跳过标定
```

反汇编早已证明 **+0xA0 = 数据指针、+0xA8 = 读写锁**（`DestroyInventoryList` 里
`lea rsi,[rcx+0xA0] / lea r15,[rsi+8]`）。这个键的意义是**一行恢复**：万一自动判据又被什么
场景卡住（日志表现为整局 `invOff=未标定`），把这里改成 `0xA0` 重启游戏即可恢复判空，**不用换 DLL**。
非法值（既不是 0xA0 也不是 0xA8）⇒ WARN + 忽略，仍走自动标定。

### 3.4 诊断同步

- 成功行：
  `inventory calibration: off=+0xA0 强证据胜场=…（不同引用=…）反证=… 弱票=… 形状坏=… 中性=… checks=… rounds=… -> 搜空判空**启用**`
- 未成功行（rounds==1 与 rounds==40 各一条）：
  `inventory calibration: 仍在攒样本（rounds=… checks=… 胜场=+0xA0:… / +0xA8:… 反证=…/… 不同引用=…/… 弱票=…/… 形状坏=…/… 中性=…/… 游标=…）`
- 末轮样本明细新增 `st=候选A/候选B` 分档字母（`G` 强证据 / `E` 形状对但空 / `X` 形状坏 /
  `N` null / `R` 读不到），例：
  `| [1] ref=FF04688E base=0001913F CONT st=N/N size=-1 obj=00000000`
  ⇒ **下次任何标定沉默，一眼就能分清「null」「读不到」「形状坏」**。
- 启动日志（`config:` 段）新增一行：
  `config: inventoryListOffset=0 -> 自动标定（★ 订正 R18：强证据胜场 + 反证闸门；万一整局 invOff=未标定 ⇒ 把它写成 0xA0 即可恢复判空）`

★ 颜色 / 通道数（仍 14）/ ESM / Papyrus / 判空语义 / 其余判据**一字未动**。

## 六、经验（本轮）

1. **「累计计数」当闸门 = 迟早自杀**：采样范围一变（轮转）、场景一脏（几个读不出形状的引用），
   累计的失败数就再也不回落 ⇒ 判据永久失效。**闸门要么是可回落的、要么必须是「反证」而不是
   「失败」**。
2. **「null」不是反证**：它经常是「没有这个东西」的**合法状态**（本处 = 没有库存清单），
   把「不知道」和「不成立」混在一个计数器里，是三次标定事故的共同形态（与 `docs/35` / `docs/40`
   的「答不了时也答否的查询不能做不可逆决策」是同一条教训）。
3. **有区分度的证据要「同对象对比」**：同一引用上两个候选不可能同时成立 ⇒ 一次对比胜过几十票
   绝对计数；本轮的判据本质是「把标定问题变成一个二选一对照实验」。
4. **给「自动学习」配一个手动兜底**：反汇编已经给出确定答案（+0xA0）时，一个 INI 键就能把
   「学习失败」从「整局功能失效」降级成「改一行重启」。
5. **诊断要能分清「不知道」的四种形态**（null / 读不到 / 形状坏 / 空）—— 本轮日志把
   `st0/st1` 直接打进样本明细，是下一次排查不用再猜的前提。
