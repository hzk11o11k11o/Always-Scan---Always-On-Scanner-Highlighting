## 2. 根因（读代码即可确认，不是内存读错）

`CalibrateInventory()`（v4.3 起）的采样循环：

```cpp
for (std::uint32_t i = 0; i < limit && sampled < kInvCalibPerRound; ++i) { … }
```

**每轮都从 `i = 0` 开始** ⇒ 40 轮采到的是**同一批引用**（当前 cell 引用数组里的
前 4 个 CONT / ACHR）。用户那一局那 4 个恰好都是**空容器**：

- `size == 0` ⇒ 只算**弱票**（`++invVotes`），拿不出强证据；
- 强证据（第一条目 `object` 是合法 TESForm）**永远拿不到** ⇒ `strong == 0`；
- 采纳条件 `votes >= 3 && bad <= 2 && **strong >= 1**` ⇒ **永远不采纳**；
- `bad == 0` 说明采样本身没读到垃圾 —— 偏移没问题，纯粹是**样本挑得太窄 + 太死**。

★ 为什么不能靠「多等一会儿」自救：这一局 40 轮快采（每 200ms 一次）之后降频到每 4 秒一次，
游标仍然在数组头 ⇒ 采到的还是那 4 个空容器，再等一小时也没用。

## 3. 修法（三处，都在 `CalibrateInventory`）

| # | 改动 | 说明 |
| --- | --- | --- |
| ① | **轮转采样** | 新增 `State::invCalibCursor`：每轮从游标处往后取样本，游标停在本轮停下的位置（扫到数组尾回数组头）⇒ 一个场景里的容器 / ACHR **都有机会被采到**，不再只认前 4 个 |
| ② | **玩家自己当一个样本** | 玩家排第一（`RE::PlayerCharacter::GetSingleton()`）：背包里必然有东西（开锁器 / 信用币…）⇒ **正常第 1 轮就拿到强样本**。★ 玩家样本**只投赞成票**：形状不过时**不计 `bad`** —— 否则 `bad <= kInvCalibMaxBad`(2) 这道闸门会让标定永久卡死 |
| ③ | **末轮样本留痕（诊断）** | 新增 `State::InvCalibSample invLastSample[4]`：记 `ref / base / size / 首条目 object / 是否 ACHR`；`仍在攒样本` 那条日志把样本摊开打出来（`[0] ref=… base=… CONT size=0 obj=00000000`）⇒ 下次万一还攒不到，**一眼分清**「采到的都是空容器」还是「根本读不出形状」 |

★ **底线不变**：仍然要求 `strong >= 1` 才采纳 —— 没被真物品验证过的偏移**绝不进热路径**
（v4.2 / v4.3 的教训，`docs/12`）。本轮只是把「样本从哪来」修好，没有放松任何判据。

## 5. 验收判据

1. **启动 / 很快出现的标定行**：`inventory calibration: off=+0xA0 ok=… strong=… -> 搜空判空**启用**`
   （正常第 1 轮就出现；**不该**再出现整局 `invOff=未标定`）。
2. ★ **核心**：把一个容器 / 一具尸体拿空 ⇒ **约 1.5 秒后描边消失**；
   统计行 `搜空: empty=` 持续增长、`invOff=+0xA0`。
3. 若仍出现 `仍在攒样本` ⇒ 直接看它后面的**样本明细**：
   - `size=0` 的样本占多数 ⇒ 那一片确实全是空容器（多走几步就会补上）；
   - `size=-1`（形状不过）⇒ 才需要怀疑偏移 / 内存读（把这几行发出来）。
4. 不回归：F8 / 扫描仪自愈 / 展示柜拿空即灭 / 换场景不崩 / 活人一个都不亮 / 配色。

## 6. 经验（可复用）

1. **★ 「功能没了」先看「功能的前置标定」**：本 MOD 的判空链路有一道**安全闸**
   （标定成功才启用），本轮现象（拿空不灭）与判据坏掉的表象**一模一样**，
   但日志里 `invOff=未标定` 一行就把它区分开了 ⇒ **安全降级必须留下「我降级了」的日志**
   （v4.11 那次教训的正面应用）。
2. **★ 采样一定要「轮转」**：任何「每轮从头扫 N 个」的采样/预算逻辑，
   在「目标分布不均」的场景里都会退化成「永远只看前 N 个」——
   分片遍历（R3）早就解决了引用遍历的问题，标定这一处当时漏了。
3. **★ 找样本时「自己」往往是最好的样本**：玩家的背包是**必然非空**的库存，
   一次采样就能证明偏移正确；比在场景里碰运气找装有东西的容器强得多。
4. **★ 诊断留痕要「留原始字段」**：`strong=0` 只说明「没拿到强样本」，
   加上 `size` / `object` 之后才分得清是「空」还是「读错了」——
   下一条日志的价值 = 它能否**唯一确定**一个原因。
