## 3. 崩溃点 A：`SAS+0x4098A`（10 次 · 主崩溃）

### 3.1 符号化

```
> python tools\re\pdbsym.py "<SAS_AlwaysScan.dll>" 7FFFD9070000 4098A
SOURCE : D:\workspace\starfield mod\always scan\tools\commonlibsf-main\lib\commonlib-shared\src\REL\IDDB.cpp : 457  (+0x7)
```

`IDDB.cpp:457` = `IDDB::GetOffset...` 里的 **Address Library v5 表查询**：

```cpp
const auto offset = static_cast<std::uint64_t>(m_v5[a_id]);   // ← 本行
```

（`m_v5` 声明为 `std::span<std::uint32_t>`，数据直接指向地址库文件映射，见 `REL/IDDB.h:69`。）

### 3.2 反汇编（从函数入口 0x40790 起解析，指令边界已核验）

```asm
0004093B  4883bf8800000000     cmp  qword ptr [rdi + 0x88], 0   ; m_v5.size == 0 ?
00040943  753e                 jne  0x40983                     ; 非空 → 查询
00040945  ...                                                    ; 组装 REX::FAIL 消息（行号 0x1C7 = 455）
00040983  488b8780000000       mov  rax, qword ptr [rdi + 0x80] ; rax = m_v5.data
0004098A  8b1cb0               mov  ebx, dword ptr [rax + rsi*4]  ; <=== 崩溃：m_v5[a_id]
0004098D  85db                 test ebx, ebx
0004098F  0f85b4000000         jne  0x40a49                     ; offset != 0 → 返回
```

> `rdi` = IDDB 实例；`+0x80` = m_v5.data、`+0x88` = m_v5.size（span 布局）。
> `rsi` = a_id。**v5 分支是裸索引，没有边界检查** —— 对照 `IDDB.cpp:433-449` 的 v0 分支
> （`std::lower_bound` + `it == m_v0.end()` 检查），两条路径的保护不对称。

### 3.3 现场（两份转储完全同型）

| 寄存器 | 06:54 样本（24512） | 09:07 样本（24876） | 含义 |
| --- | --- | --- | --- |
| RAX | `0x0000021C39050060` | `0x000001D039920060` | `m_v5.data`（低 12 位 = **0x060** = 映射视图 + 头部偏移） |
| RSI / RDX | `0x9756` | `0x9756` | **a_id = 38742（两次相同）** |
| RDI | `SAS+0xA5910` | `SAS+0xA5910` | IDDB 静态实例（在 SAS 内，同一位置） |
| 读地址 | `0x0000021C39075DB8` | `0x000001D039945DB8` | **= data + 38742×4（精确吻合）** |

算术验证：`data + 0x9756*4 = data + 0x25D58` → `0x1D039920060 + 0x25D58 = 0x1D039945DB8` ✔（两份都吻合）

### 3.4 关键观察（供定位）

1. **每次崩溃都是同一个查询：`m_v5[38742]`** —— a_id 固定（两份样本一致），
   这也解释了 10 次的读地址为什么低 16 位恒定：
   `data` 低 16 位（0x0060）+ `0x9756*4` 低 16 位（0x5D58）= `0x5DB8`。
2. 读地址换算到**文件内偏移 = 155,064 字节**，而 `versionlib-1-16-244-0.bin` 有
   5,099,968 字节 —— **位置本身在文件范围内，却不可读**。
   ⇒ 优先怀疑：
   - **m_v5.data 指向的映射视图此刻不可读**（视图已 unmap / 尚未建立 / 生命周期竞态），
   - 其次是「v5 数据区条目数 < 38742」（地址库条目布局/版本与请求不符）。
3. `[rdi+0x88]`（size）非 0 才会走到查询（0x4093B 的空表检查通过），
   说明 IDDB 自认为表是有效的 —— 这与「视图失效/指针过期」的假设互相印证。

### 3.5 建议排查

1. 在查询处加诊断（临时）：打印 `a_id / data / size`，并检查 `data` 与 `data+size*4` 的可读性
   （或直接用 SEH 包住读取）；
2. 找出 **谁持有 `SAS+0xA5910` 这个 IDDB 实例**、以及 `REX::FMemoryMap` 的构造/析构/重建时机
   （是否有 reload / 多线程首次触发的路径）；
3. 把 **38742（0x9756）反查为符号**（Address Library 的 ID→符号数据库）⇒ 直接指向调用的
   `REL::ID` 与源码位置；
4. 复核 SAS 编译用的 commonlibsf 版本与 `versionlib-1-16-244-0.bin` 的匹配状况；
5. 可选（上游）：给 v5 分支补边界检查（`a_id < m_v5.size()`），把静默崩溃变成可诊断的 FAIL。

## 4. 崩溃点 B：`SAS+0x2023A`（09:50:46 · 本次）

### 4.1 符号化

```
SOURCE : ...\always scan\plugin\src\AlwaysScan.cpp : 4442  (+0x0)
```

= `RefLootState()`（判空链路）里的库存数组读取：

```cpp
const auto  size = *reinterpret_cast<const std::uint32_t*>(inv + kOffInvData);      // 4442 ← 本行
const auto  cap  = *reinterpret_cast<const std::uint32_t*>(inv + kOffInvData + 4);  // 4443
```

### 4.2 反汇编（边界已核验）

```asm
00020220  488d81fffffeff        lea  rax, [rcx - 0x10001]       ; IsPlausiblePointer()
00020231  493bc1                cmp  rax, r9                    ; r9 = 0x7FFFFFFEFFFD
00020234  0f87ec030000          ja   0x20626                    ; 不合格 → return -1
0002023A  448b7128              mov  r14d, dword ptr [rcx + 0x28]  ; <=== 崩溃：size = *(inv+0x28)
00020250  8b412c                mov  eax, dword ptr [rcx + 0x2c]   ; cap
0002027C  4c8b7930              mov  r15, qword ptr [rcx + 0x30]   ; data
```

### 4.3 现场

| 寄存器 | 值 | 说明 |
| --- | --- | --- |
| RCX | `0x1A486` | 从 `*(a_ref + g_invOff)` 读出的「库存指针」——**垃圾小整数、非 8 字节对齐** |
| R8 | `0x1CDA61C3CE0` | a_ref |
| 读地址 | `0x1A4AE` | = 0x1A486 + 0x28（与转储 param1 完全一致） |

**根因**：`IsPlausiblePointer()`（`AlwaysScan.cpp:1480`）只查
`> 0x10000 && < 0x7FFFFFFFFFFF`，`0x1A486` 轻松通过 ⇒ 直接解引用崩溃。

### 4.4 建议

1. `IsPlausiblePointer` 至少加 **8 字节对齐**（`(p & 7) == 0`），可挡掉本类垃圾值；
2. 判空链路的解引用统一走 `SafeReadMem` / `IsReadable`（SAS 已有这些工具；
   本处 4426/4442/4443/4453 及 `LootProbe`/`ContProbe` 同类位置都是裸读）；
3. 复核「a_ref 处于销毁/复用过渡态」的可能（该崩溃发生在传送/cell 切换完成后约 1 秒）。
