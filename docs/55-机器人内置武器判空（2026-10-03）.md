## 二、根因

### 2.1 离线取证（三步，脚本可复跑）

1. **认物品**（`tools/re/esm_find_by_fid.py`）：

   ```
   WEAP 001DC415  recflags=0x40000000  EDID = crModelA_CombatRightGun_Auto
   WEAP 001DC416  recflags=0x40000000  EDID = crModelA_CombatLeftGun_Auto
   ```
   —— 即**战斗机器人（Model A）的左右手臂炮**（`cr` = creature，生物内置武器）。

2. **看结构**（`tools/re/esm_weap_dump.py`）：这两条**没有 `MODL`（模型）**、
   **没有 `FULL`（名字）**、没有 `MOD4`；对照组 `crModelA_Equinox`（0x2C7D29，
   机器人手持的 Equinox）**有** `FULL` + `MODL` + `MOD4`。
   ⇒ 无模型 = **虚拟武器**：引擎画不出它的 3D ⇒ 搜刮面板不列出、玩家也拿不走
   （B 社对「生物内置武器」的标准做法）。

3. **查标志覆盖**（`tools/re/esm_creature_weap_probe.py`）：
   - `cr*` / `Creature*` WEAP 共 **58** 条：**24 条带 0x04**（非玩家物品，如
     `crTurretLaser_Auto` 0x1E7431、`crModelA_Equinox` 0x2C7D29）—— 这些
     v4.5 的规则本来就能覆盖；
   - **34 条不带 0x04**：其中 22 条有 `MODL` + `FULL`（`crRocketlauncher_Hunter`、
     `Crew_Elite_*` = **正常的可拿武器**，绝不能跳），**剩下 12 条是
     `crModelA_*` 系列（全部无 MODL、无 FULL）** = 本次的真正目标。
   - 再穷举全表（`tools/re/esm_nomodl_weap_probe.py`）：全 esm 的 WEAP 里
     **「无 MODL 且无 0x04」正好 14 条** —— 12 条 `crModelA_*` + `UnarmedHuman`
     （虚拟徒手）+ `GasTrapDummy`（虚拟毒气武器）。**名单完整性由脚本证明**。

### 2.2 一句话根因

机器人手臂炮是**身体部件**（无模型虚拟武器、面板不显示 / 拿不走），但记录里
**漏标**了 0x04（Non-Playable）⇒ 判空的两条「拿不走的东西不算有东西」规则
（v4.5 的 `SkipNonPlayableLoot` / v4.6 的 `SkipEquippedLoot`）**一条都盖不到它们**
⇒ 尸体**永远**被判「有东西」⇒ 描边不灭。

（为什么不能靠「fl=0 ⇒ 面板显示 ⇒ 应该能拿」的既有实证：那条实证成立于
**有模型的普通物品**；无模型虚拟武器是引擎过滤的第二条隐藏规则 —— 这次的
数据正是它的第一批反例。）

## 三、修法（只改 `plugin/src/AlwaysScan.cpp` + `main.cpp` 注释/加载行 + INI）

1. **常量区新增名单** `kBuiltinLootForms`（14 条，带逐条注释与完整取证说明）。
2. **新增判断函数 `IsCreatureBuiltinForm()`**：`SafeReadMem(obj + 0x28)` 读
   formID → 比对名单；读不出来返回 false（当「可拿」，由形状校验兜住）——
   与 `IsNonPlayableForm` 同一姿势。
3. **`RefLootState` 跳过链新增第三路**：`np（0x04）→ eq（kSlotMask）→ bi（内置武器）`；
   命中即 `continue`（不算「有东西」）。快照模式同样标 `uncertain`（与 np / eq 一致）。
   每个 base **首次命中**打一条日志（每会话 ≤ 4 条）：
   `loot: 跳过「生物内置武器」base=001DC415（无模型虚拟 WEAP ⇒ 面板不显示 / 玩家拿不走；★ 订正 R16）`。
4. **诊断同步**（口径与判定链逐字对齐）：
   - 统计行 `判空跳过: np=… eq=… **bi=…**`（新增计数 `lootSkipBuiltin`）；
   - `loot probe:` 新增第四桶 `builtin= biTotal=`，明细行加 `bi=0/1`；
   - `cont probe:` 新增 `skipBi=` 与明细 `bi=`，`sumKeep`（可拿合计）口径同步
     （否则「探针说还有可拿的、判定却说空」会误报不一致）。
5. **新 INI 键 `SkipBuiltinLoot`**（默认 1，0 = 关）+ 模板长注释（背景 / 名单 /
   为什么偶发 / 什么时候设 0）；启动日志 `config: … skipBuiltinLoot=`。
6. `main.cpp` 加载行追加「★★★★★ 订正 R16」识别标记。

**★ 误灭面（如实记录）**：名单里 14 条全是**无模型虚拟武器**（玩家在任何正常
路径都拿不走）。若将来 B 社改数据让某一条真能拿了，表现为「有东西却不亮」——
把 `SkipBuiltinLoot=0` 即可整体退回（不用换 DLL）。新增同类武器（DLC / mod）时，
重跑 `tools/re/esm_nomodl_weap_probe.py` 把新 FormID 补进名单即可。

**★ 颜色 / 通道数（14）/ ESM / Papyrus / 其余判据一字未动。**

## 六、经验

- **「拿不走」的判据要覆盖数据的全部实现方式** —— 0x04 标志只是一条路，
  「无模型虚拟武器」是第二条（这次的第一批反例）；「fl=0 即面板显示」的实证
  只成立于**有模型**的普通物品。
- **穷举比推断可靠**：先把「无 MODL 且无 0x04」在全表跑一遍（正好 14 条），
  再动手 —— 名单是**证明出来**的，不是猜出来的；`Crew_Elite_*` 等 22 条
  「无 0x04 但有模型」的可拿武器因此**没有被误伤**。
- **「偶发」往往意味着残余条件的组合**：这里 = 「那只 `fl=0` 的手臂炮」
  × 「其余东西已被拿空」；把日志里同一批样本（4 具机器人）摆在一起，
  条件就自己浮出来了。
- **探针 / 统计的口径必须与判定链逐字对齐**（新增一路跳过，就把
  `bi=` / `skipBi=` / `builtin=` 全部补齐），否则下一次「探针说是可拿的、
  判定却说空」的假不一致会把排查带偏。
