## 二、根因

**「已确认拿空」是一个应该跨场景保留的事实，但实现只把它存在了按指针键的判决表里。**

```
DisplayCaseVerdict.lastKnown == 2   （粘性：拿空即灭）
  └─ 存在 g_state.displayCaseVerdict  ：unordered_map<const TESObjectREFR*, …>
       ├─ ResetForNewScene()（载入画面关闭 / 换 cell）⇒ clear()  ← 粘性经此全丢
       └─ cell 卸载 / 重载 ⇒ 引用对象重建 ⇒ 指针失配      ← 即使不 clear 也命不中
```

⇒ 玩家「远离」= 过门 / 快速旅行 / 走出 cell 环（内景 ≠ 连续过渡，一律触发 reset），
回到原场景时判决表是空的 ⇒ `DisplayCaseReadsEmpty` 返回「内容未知」⇒ 箱子**照常亮**
（v4.9 口径），而它的内容已经拿空、箱子本身在关闭状态下又读不出「空」——
这就是用户看到的「远离后又重新亮起」。

副因（同源）：即使不触发 reset，远处 cell 卸载 / 重载后引用对象重建，指针键同样失配。

## 三、修法（只改 `plugin/src/AlwaysScan.cpp` + `main.cpp` 注释 / 加载行 + INI 注释）

**新增第 ⑤ 条判据「跨场景粘性」**：把「已确认拿空」**额外登记进一份 FormID 键的粘性表**：

```
MarkDisplayCaseEmptied（任何判据落粘性时）
  ⇒ ds.lastKnown = 2 + DcStickyFidAdd(ref->GetFormID())     // FormID 键，跨场景保留
DisplayCaseReadsEmpty
  ⇒ 先查 FormID 粘性表：命中 ⇒ 返回 kDcEmptyStickyFid（why=5）⇒ 判空（熄灭）
ResetForNewScene
  ⇒ 只清指针键判决表；**FormID 粘性表不清**（FormID 是值、不会悬垂）
自愈（三条路，任一条即恢复「重新亮」）
  · put 事件（往里放东西）  ⇒ DcStickyFidErase
  · NoteDisplayCaseOccupied（再读到内容）⇒ DcStickyFidErase
  · 表满 ⇒ FIFO 覆盖最老一条（上限 kDcStickyFidMax = 512）
```

**同一轮修订 R15 阈值**：`kDcEmptyNoContentMs` / INI 默认 **2000 → 3000ms** ——
依据 = 本局日志实证投影可**晚到 2.13 秒**（2000ms 曾误灭一例，见 §一）。
3000ms 对上述观测仍有 0.87 秒余量；`DisplayCaseEmptyNoContentMs=0` 仍可关。

**诊断**：

- 新原因码 `kDcEmptyStickyFid = 5`，文案「粘性（已确认拿空·跨场景保持）」；
- 新日志 `display case sticky kept (跨场景粘性·保持熄灭) [why=5]: ref=…`（每 ref 每场景首次命中一条）；
- 新日志 `display case sticky cleared (又读到内容 / 有东西了) [★ 订正 R17]: ref=…`；
- `ContProbe` 的 `st=` 新增第 4 档：**3 = 跨场景粘性命中**（0=未知 1=有东西 2=本场景已确认拿空）；
- 统计行 `展示柜拿空=「空箱判空=」` 之后新增 **`粘性复用=`**（窗口内粘性恢复熄灭次数）；
- `reset (…)` 行尾追加 `| 展示柜粘性保留=N 条（★ 订正 R17：跨场景不丢）`；
- 启动日志那条 `config: containerLootEvents=…` 追加 `跨场景粘性（★ 订正 R17）= 开（…）`。

**如实记录的取舍（唯一新误灭面）**：读回**更早的存档**（箱子在那边还有东西）时，
粘性偏保守（箱子可能不亮）—— **打开它一次**（投影出现）或放东西即自愈；
反方向（拿空后重新亮起）正是用户反复报告的问题，两害相权取此。
粘性表**不落盘、不跨进程**（会话级）。

★ 颜色 / 通道数（仍 14）/ ESM / Papyrus / 其余判据一字未动。

## 六、经验

- **「事实的作用域」必须和它的生命周期一致**：`ResetForNewScene` 清指针键缓存是对的
  （旧指针可能悬垂），但「已确认拿空」是**世界里的事实**，不属于「旧世界」——
  清缓存时要把**值键**（FormID）的那一份单独留出来。这与 docs/38（按存档 / 按星球
  作用域）是同一条教训的第三次出现：**先问「这个事实的作用域是什么」，再决定在哪里存**。
- **指针键 = 场景内的临时身份**：cell 卸载 / 重载、换场景、读档都会让它失配或悬垂。
  凡是「要跨场景保留」的状态，都要有成对的「值键」表示（FormID / base / 时间戳）。
- **补集思维（docs/54 的延伸）**：加判据 ④ 时问过「这个判据的补集谁负责」；
  这一轮要问的是「**这条判据的存续谁负责**」—— 判据成立之后，结论要活多久、
  在哪里活、什么时候失效，同样是判据的一部分。
- **阈值型判据的取值要被日志反复校准**：投影装填期「0.4~0.7 秒」是实测值，
  但本局抓到了 **2.13 秒**的反例 ⇒ 默认阈值从 2000 提到 3000（仍留余量）。
  **实测数据的分布尾部**（而不是中位数）才决定阈值。
