# 12 · 尸体高亮 + 容器/尸体「搜空即熄灭」（v4.2）

> 用户实测反馈（三条，2026-09-18）：
> ① 「地图内有一些预先放置的尸体，没高亮」；
> ② 「打死的敌人尸体没高亮」；
> ③ 「已经拿空的容器仍在高亮，拿完了就应该不亮了（**敌人尸体也要做同样处理**）」。
> 另补充：④ 「**怪物的尸体**也要和人类的尸体同样处理」。
>
> 本文记录定性、实现与验收判据。相关代码只在 `plugin/src/AlwaysScan.cpp`（DLL），
> 不需要动 ESM / Papyrus。

## 0. 结论速览

| 反馈 | 根因 | 修法 |
| --- | --- | --- |
| ①②④ 尸体不亮 | 旧版分类是**纯 base form 类型白名单**，而 `NPC_` / `LVLN` / `ACHR` 是**红线**（「活人不亮」）⇒ 尸体被一起挡掉 | 新增 `ClassifyRef()`：**按引用自己**分类 —— ACHR 引用先判死活，死的进新的 `corpse` 类别；`base = NPC_/LVLN` 的普通 REFR 也归 corpse |
| ③ 搜空还亮 | 旧版只按类型挑目标，**从不看库存** ⇒ 空箱子照常亮 | `RefLootState()`：读引用的库存列表，**把所有条目 stack 的 count 加起来**，和为 0 ⇒ 不进候选集合 ⇒ 由宽限期（1.5 s）摘掉描边 |
| ④ 怪物尸体 | 本来担心要单独处理 | **不需要**：Starfield 没有 `kCREA`，生物也是 `NPC_` 记录、也用 `ACHR` 引用摆 ⇒ 与人类尸体**同构**，一套规则全覆盖（离线数据已证，见 §1.3） |

## 1. 离线实证（先钉死数据形态，再写代码）

新增两个一次性统计脚本（放在不入库的 `out/`）：
`out/achr_flags_scan.py`（ACHR/REFR 记录 flags 直方图）、
`out/dbg_corpse_bases.py`（带 Starts Dead 的 ACHR 引用 → base 记录的 EDID）。

### 1.1 全量 `Starfield.esm`（1.16.244.0）统计

```
ACHR: n=9530  StartsDead(0x200)=2283  StartsUnconscious(0x2000)=193  InitiallyDisabled(0x800)=1843
   flags&0x3E00 top: 0x0000x6079, 0x0200x1235, 0x0A00x1044, 0x0800x707, ...
REFR: n=3291860  StartsDead(0x200)=487  StartsUnconscious(0x2000)=0
```

⇒ 「预先放置的尸体」在数据里就是 **ACHR 记录 flags `0x00000200` = `Starts Dead`**，
占 ACHR 的 24%（2 283 条）；其中 1 044 条同时带 `Initially Disabled`（不加载 = 不该亮）。

xEdit 的 Starfield 定义（`wbDefinitionsSF1.pas:16542`）确认这两个位的名字：
`{0x00000200} 'Starts Dead'` / `{0x00002000} 'Starts Unconscious'`。

### 1.2 判死的第三个信号：运行时 `Actor::boolBits` 的 kDead 位

`Actor::boolBits @+0x208` 的 `bit11 = kDead`（commonlibsf 的 `Actor::IsDead()` 就是读它）。
上一代项目用 `tools/re/scan_disp.py` 反查过引擎代码：
`or dword ptr [reg+0x208], 0x800`（战死置位）/ `and ..., 0xfffff7ff`（Resurrect 清位），
语义吻合。**打死敌人走的就是这一条** ⇒ 反馈 ② 靠它。

★ 但**不能只信它**：上一代项目实测过一具明确可搜刮、却读不到 kDead 位的身体
（`corpse=21/0`）⇒ 所以本版把「记录标志 Starts Dead」也当作判死依据（静态数据，
与引擎有没有置运行时位无关）。两者**取或**。

### 1.3 预置尸体的 base 都是 `NPC_`（人类 + 怪物同构）

dump 带 `Starts Dead` 的 ACHR 引用（`out/dbg_corpse_bases.py`）——样本：

```
ref=003B5D10 baseEDID=SE_KT14_JerianThybulle_Corpse      ← 任务尸体（人类）
ref=0022E84E baseEDID=Biome_Prey_Corpse                  ← ★ 星球生物（怪物）尸体
ref=002254F5 baseEDID=MQ207C_RafaelAguerroCorpseInLab
ref=003A2CF5 baseEDID=UC_NA_TopherCorpse
ref=00177C75 baseEDID=Loot_Corpse_MinerF_Fresh01         ← 可搜刮的矿工尸体
```

- **生物尸体（`Biome_Prey_Corpse`）与人类尸体同构** ⇒ 用户补充的第 ④ 条天然满足；
- 9 530 个 ACHR 引用的 base **全部**是 `NPC_` 记录（Starfield 没有 `kCREA`，
  生物 / 机器人 / 炮塔都是 `NPC_`）；全量 329 万个 REFR 里 base 命中 `NPC_/LVLN` 的为 **0**
  （即原版没有「用普通 REFR 摆尸体道具」这种做法 —— 代码里仍保留这条保险，见 §2.2）。

### 1.4 ★ 为什么「Starts Unconscious」默认**不算尸体**

同一份 dump 里带 `0x2000` 的样本是：

```
ref=0018DF25 baseEDID=LvlTurretShort_LC116                  ← 炮塔（初始停机）
ref=00240997 baseEDID=LvlRobotModelA_LC116_Industrial_Aggro ← 机器人（初始停机）
```

⇒ 这个标志在数据里是「**初始处于停机 / 倒地状态的单位**」（炮塔 / 机器人 / 被打倒但没死的人），
**不是尸体**；把它们描上边会很怪，而且「倒地的人」会自己站起来（违反「活人不亮」红线）。
因此默认 `CorpseUnconscious=0`，只作为可选开关（INI 里已注明理由）。

## 2. 实现（全部在 `plugin/src/AlwaysScan.cpp`）

### 2.1 新增类别 `Category::kCorpse`

- 枚举追加在最后（保持既有 6 个类别下标不变），`kCategoryName` + `"corpse"`；
- INI 键：`StateCorpse`（默认 **9 = 橙，与容器同色**）、`EnableCorpse`（默认 1）、`ColorCorpse`；
- 日志里 `category (本轮选中)` / `config: stateByCategory` 自动带上 corpse。

### 2.2 判死：`ClassifyRef()`

```
ACHR 引用：
    kDead 位(+0x208 bit11)  ∨  记录标志 Starts Dead(0x200)   ⇒ corpse 类别
    （Starts Unconscious(0x2000) 且 INI 开了 CorpseUnconscious ⇒ corpse）
    否则 ⇒ -1（活人 / 生物 / 炮塔 / 机器人，一律不亮，红线）
其它引用：base 类型 ∈ {NPC_, LVLN} ⇒ corpse（「姿势固定的尸体道具」，原版没有，纯保险）
其余情形 → 走原来的 ClassifyBase（类型白名单）
```

- 全部是**纯内存读**（ref 的 `+0x2E` formType、`+0x20` formFlags、`+0x208` boolBits），零引擎调用；
- `+0x20 / +0x2E` 是 **TESForm 基类**成员（本项目长期实测读法正确，另加了 3 条 `static_assert` 钉死）；
- 诊断 `corpse probe:`（每会话最多 12 条）：打 `ref / base / formFlags / boolBits`，
  用户报「某具尸体没亮」时可直接对号入座。

### 2.3 判空：`RefLootState()` + `CalibrateInventory()`

- `TESObjectREFR::inventoryList` 是 `BSGuarded<BGSInventoryList*, BSReadWriteLock>`，
  commonlibsf 里成员顺序标着 `??`（data 在前还是在后不确定）⇒ **两个候选偏移 `0xA0 / 0xA8`
  都探测**：每会话一次，拿**容器**样本做形状校验
  （指针合理 + 可读 0x38 + `+0x28` 处 BSTArray 三元组自洽 + 非空时 data 可读），
  通过 3 个以上且坏样本 ≤2 就用它；都不行 ⇒ **永久降级**（不判空，容器/尸体照常亮）并打 WARN；
- 热路径判空：指针合理 → `+0x28` 的 `size/cap` 自洽 → `size==0` 直接判空；
  否则**逐条目把 stack 的 count 加起来**（上限 128 条目 / 1024 个 stack），
  **和为 0 才算空**。
  ★ 为什么要数 count：物品被拿光后引擎**可能留下 count = 0 的空 stack / 空条目**，
  只看 `data.size()` 会把已经搜空的箱子永远当成非空；
- ★ 热路径**零引擎调用、零 VirtualQuery**（标定完成后）；任何一步形状不对 ⇒ 返回「未知」⇒
  **按「有东西」处理（照常亮）** —— 最坏结果与旧版一致，绝不会因读错内存而崩。

### 2.4 接进主循环

```cpp
bool isCorpse = false;
const int cat = ClassifyRef(ref, base, isCorpse);      // ← 取代 ClassifyBase(base)
... 类别开关 ...
if (isCorpse || cat == kContainer) {                   // ← 判空只对容器 / 尸体做
    if (cfg.skipEmptyLoot && g_invOff) {
        const int loot = RefLootState(ref);
        if (loot == 0) { ++emptySkips; continue; }     // 空 ⇒ 不进候选 ⇒ 宽限期后摘掉
        if (loot < 0) { ++lootUnknown; }
    }
}
```

## 3. 风险与降级（都设计成「最坏 = 旧行为」）

| 风险 | 兜底 |
| --- | --- |
| `inventoryList` 偏移标定失败 | 不判空，容器 / 尸体照常亮（日志 WARN），**不崩** |
| 库存内存形状读到垃圾 | 任一步校验不过 ⇒ 「未知」⇒ 照常亮 |
| 「Starts Dead 的 ACHR」被任务复活 | 极罕见；且只要身上没东西就不会亮 |
| 活人误亮 | 判活规则只有「ACHR 且非死」一条，默认连 unconscious 都排除；INI 可回退 `EnableCorpse=0` |
| MSTT 等原本不亮的东西 | 分类规则未动，仅新增 corpse 一类 |

## 4. 实测验收点（本轮）

1. **尸体亮**（橙，默认与容器同色）：
   - 打死的敌人 / 生物 ⇒ 立刻亮；
   - 预置尸体（如 `Loot_Corpse_*`、任务现场尸体）⇒ 进半径就亮；
2. **活人一个都不亮**：城市里站着看一分钟，NPC / 生物 / 炮塔 / 机器人都不该有描边；
   `corpse probe` 若出现「跳过：Starts Unconscious」即为**预期**（想亮就 `CorpseUnconscious=1`）；
3. **搜空即灭**：把一个箱子 / 一具尸体拿空 ⇒ ~1.5 秒后描边消失；
   `corpse (窗口内累加)` 行的 `empty=` 持续增长；
4. **标定成功**：启动日志出现一次 `inventory calibration: off=+0xA0 或 +0xA8 … -> 搜空判空**启用**`；
   若出现 `FAILED … -> 搜空判空**关闭**` ⇒ 判空没生效（容器照常亮），把这一行发出来；
5. 不回归：F8 开关、用原版扫描仪后自动重挂、换场景不崩、`timing2` 无大值。

## 5. 经验（可复用）

1. **先扫数据再写判据**：`Starts Dead` 2 283 条 vs `Starts Unconscious` 193 条，
   以及「后者是炮塔/机器人」这条样本，直接决定了「哪个默认开、哪个默认关」——
   这类判断**不该靠猜**，一次 mmap 扫全量 ESM 只要几分钟。
2. **静态数据 + 运行时状态 取或**：记录标志（Starts Dead）与运行时位（kDead）各有盲区，
   单独用任一个都会漏；两个都用，最坏也只是「多亮一具尸体」。
3. **判空要看 count，不看条目数**：引擎的「0 件空条目」会让「按条目数判空」永远判不出来。
4. **新功能一律做成「失败即降级到旧行为」**：偏移标定失败 → 不判空；形状校验不过 → 照常亮。
