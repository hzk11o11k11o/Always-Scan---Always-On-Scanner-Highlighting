## 一、证据链

### 1.1 用户那一局的日志（`SAS_AlwaysScan.log`，2026-09-27 07:08~07:12，v5.1 未订正版）

```
[07:11:51] channel (自建颜色通道): 状态=已就绪 通道=13/13 已挂=66 …
[07:11:51] planet targets (窗口内): 未扫描=480 已扫描=240 | 判据: 查询=826 命中=256 链失败=171 缓存=60 …
           | 引擎状态: 问=833 已扫描=7 未扫描=655
           | 按引用记忆(★v5.1): 命中=236 绿=20 青=0 总量=20
           | 引擎状态表: 条目=18446744073709551615 读=0 绿=0 青=0 无条目=6417
```

三条硬证据：

| 观察 | 含义 |
| --- | --- |
| `条目=18446744073709551615`（= `0xFFFFFFFFFFFFFFFF`） | 读到的根本不是红黑树的 `_Mysize`，而是**别处的填充数据**（该 RVA 在文件里就是 32 个 `FF`） |
| `读=0`（整局 6417 次探针一次都没命中） | 「引擎亲手画过 4/5」这条**最硬的证据从未生效** |
| `问=833 已扫描=7 未扫描=655` ⇒ **差 171（20%）** | 主判据 `GetOutlineState(ref)` 有 20% 的询问**既不是 1 也不是 2** = 答 **0 = 不知道** |

「已扫描=7」的 7 个目标全都靠主判据兜住（日志里 `判据 = 引擎自己的扫描状态`）；
其余绝大多数「已扫描」结论来自资源链（LVLI 矿物）；**植物**（产出是 MISC）只能靠主判据，
所以那 20% 里只要有一个是植物，用户看到的就是「扫过了却还是青色」。

### 1.2 反汇编复核（1.16.244.0，`tools/re/disasm.py`）：树头是 **0x5F39CE0**

v5.1 的注释写着「`lea rbp,[rip+0x4764066]` ⇒ RVA 0x5949CE0」——**少看了一位**。
capstone 打印的是 disp 的十六进制值，4 字节 disp = **0x04764066**（不是 `0x4764066`）：

```
017D5BF7  488b1de2407604   mov rbx,[rip+0x47640e2]   ; rbx = *(0x17D5BFE+0x047640E2) = *(0x5F39CE0) = 哨兵
017D5BFE  488b4308         mov rax,[rbx+8]           ; rax = 哨兵+8 = 根
017D5C73  488d2d66407604   lea rbp,[rip+0x4764066]   ; rbp = 0x17D5C7A+0x04764066 = 0x5F39CE0 = 树对象
017D5C73+…              call 0x3222e0               ; 插入（rcx = rbp = 树对象）
003222EA  48ff4108         inc qword ptr [rcx+8]     ; ★ 树对象+8 = _Mysize（条目数）
003222F1  488b39           mov rdi,[rcx]             ; ★ 树对象+0 = _Myhead（哨兵）
017D4B88  488b3d51517604   mov rdi,[rip+0x4765151]   ; 拆扫描仪 HUD：rdi = *(0x5F39CE0) = 哨兵
017D4B8F  488b07           mov rbx,[rdi]             ; 从最左节点开始遍历（键 = 节点+0x20 = REFR*）
017D4CA2  48892d3f507604   mov [rip+0x476503f], rbp  ; ★ *(0x5F39CE8) = 0 —— **放下扫描仪就清空条目数**
```

计算（都可复算）：

| 位置 | 计算 | 结果 |
| --- | --- | --- |
| `0x17D5BF7 mov rbx,[rip+…]` | `0x17D5BF7 + 7 + 0x047640E2` | **0x5F39CE0** |
| `0x17D5C73 lea rbp,[rip+…]` | `0x17D5C73 + 7 + 0x04764066` | **0x5F39CE0** |
| `0x17D4B88 mov rdi,[rip+…]` | `0x17D4B88 + 7 + 0x04765151` | **0x5F39CE0** |
| `0x17D4CA2 mov [rip+…],rbp` | `0x17D4CA2 + 7 + 0x0476503F` | **0x5F39CE8**（= 条目数，写 0） |

★ **交叉验证（最强的自洽证据）**：同一簇里的管理器数组
`kRvaOutlineManagers = 0x5F39CF0` **正好 = 树头 + 0x10**（8 字节 `_Myhead` + 8 字节 `_Mysize`）。
两个常量本来就相邻，v5.1 却把树头写成 `0x5949CE0` —— 差了约 0xEB4 万字节。
把 `0x5949CE0` 处的文件数据打出来是 **32 个 `FF`**（无关的填充/未初始化区），
这与日志里 `条目=0xFFFF…` 完全对上。

### 1.3 主判据为什么会答「0」：`GetOutlineState` 反汇编（0x1306E80）

```
01306E91  mov dl,0x2a                 ; 组件类型 0x2A = Scannable
01306E9A  call 0x2c5c90               ; 取组件
01306EA4  je 0x1306fdc                ; ★ 组件缺失 ⇒ 走「按 FormID 查知识库」那条
…
01306FBB  …（FormID < 0x01000000 的引用走这里）call 0x7b7d60 ⇒ setne/inc ⇒ 1 或 2
01307061  xor sil,sil                 ; ★★ 知识库里查不到 ⇒sil=0 ⇒ **返回 0**
01307074  inc sil                     ;    查得到 ⇒ 2
01306F9E  movzx eax,byte [rsp+0xb0]   ; （另一条路）setne al; inc al ⇒ 1 / 2
```

⇒ 返回 **0 = 引擎「不知道」**（组件缺失 + 玩家知识库没有这条记录）。
这正好解释用户日志里那 **171/833 = 20%** 的差额：**它不是「未扫描」，是「不知道」**。
v5.1 的代码只把 `== 2` 当已扫描、`== 1` 当未扫描，**0 既不计数也不特殊处理**，
于是这些目标只能靠「资源链」或「记忆」兜 —— 植物两条都没有 ⇒ 停在青色。

### 1.4 第二条：「青」记忆把判据链短路了（v5.1 的设计漏洞）

v5.1 的 ⓪（按引用记忆）与 ⓪.5（状态表探针）都写成「**只要记忆里有结论就 return**」：

```cpp
if (FloraRefKnown(a_ref, fid, &knownGreen)) { … return knownGreen; }   // ← 青也 return
```

「青」记忆的唯一来源是「举着扫描仪时探针看到引擎画了 7/8」。一旦记下：
① 主判据 / ② 资源链**永远跑不到**，而 ⓪.5 又只能靠「探针再看到 4/5」才能翻案
（放下扫描仪后表已清空 ⇒ 基本没机会）⇒ **扫过的目标可以永久停在青色** ——
这正是用户说的「低概率、少部分」。它同时还是「举一下扫描仪就恢复」那个老现象的孪生兄弟。

## 五、经验（写给下一轮）

1. **手算 rip 相对地址是最容易错的一步** —— capstone 打印的 `[rip+0x4764066]`
   里那个 disp 是**完整 4 字节值 `0x04764066`**；少看一位就差了 ~0xEB4 万字节，
   而且**不会崩**（读到的是其它可读内存）⇒ 症状是「功能静默失效」，最难查。
   ★ 对策：**算完必须找一个相邻常量 / 相邻结构交叉验证**
   （本例 `kRvaOutlineManagers = 树头 + 0x10` 一句话就能证伪）。
2. **「探针一次都没命中」本身就是证据**：统计行要有**分母**（`读=` 与 `无条目=` 同时在涨
   而 `读=0` ⇒ 探针坏了，而不是「引擎没写」）。有分母的数字才可证伪。
3. **引擎函数会答「不知道」**：`GetOutlineState` 第三条返回路径是 **0**（组件缺失 + 知识库
   查不到），实测占 20%。把「0」当「1（未扫描）」用，就会得到「扫过却不变色」这种偶发现象；
   凡是三态（是 / 否 / 不知道）的判据，代码里必须有第三档，日志里必须能看见它。
4. **单向记忆的「否」不能短路**：缓存「是」可以（一票通过），缓存「否」只能当提示 ——
   否则任何一次误判都会**永久固化**，而用户看到的是「低概率、少部分」，
   非常难归因。规则：**能让结论变「绿」的判据永远不许被「青」挡住**。
5. **用户明确要求时，版本号一个字都不要动**：本轮所有产物（DLL / 包 / MO2）都保持
   `v5.1.0` / 公开版 `2.0`，只在启动日志里加一行「订正 R1」作为构建指纹。
