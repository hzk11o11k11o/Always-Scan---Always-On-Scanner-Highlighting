# 20 · 「覆盖太深」的终局：不是 alpha，是**填充**（DLL v4.21.0 / 发布版 1.7.3）

> 建立：2026-09-25。触发：用户实测反馈（附截图）——
>
> ```
> 1.7.2的改动没有起作用
> ```
>
> 截图内容：近处**门**是一整片米白、地上**手枪**是一整块红色，材质完全不可见
> （与 v4.19 那一轮的观感一致、看不出与「40% 不透明度」有任何区别）。

本轮把这件事**一次查到底**：先用日志排除「v4.20 没跑起来」，再用截图**逐像素**证明
「alpha 根本不被渲染消费」，最后改到**正确的开关**上 —— 引擎自己的「不填充」
（描边基色 alpha=0），物品材质从此完整可见。

---

## 一、先排除「软件层没生效」（日志证据，全部通过）

用户会话（`SAS_AlwaysScan.log`，16:58 起）：

| 证据 | 原文 |
| --- | --- |
| 新 DLL 已装载 | `SAS_AlwaysScan v4.20.0 loading (SFSE build 131408)` |
| 新配置已读到 | `config: colorAlpha（覆盖不透明度，0=保留引擎原值，255=不透明）: weapon=102 (40%), apparel=102 (40%), door=102 (40%)` |
| 覆盖已写入 | `outline colors: state=0 覆盖为 #FF2E2E <- weapon（…；不透明度 102/255（约 40%））` |
| 渲染侧参数块已更新 | `renderer params[stats]: state= 0 … 基色=#FF2E2E a=66 脉冲=#FF2E2E a=66` |

⇒ 写入链路（表 → 管理器 → 渲染侧 32 B 参数块）**每一步都有 a=66**。
**问题不在我们没写，而在「写了没人用」。**

## 二、逐像素量化：渲染 = **不透明纯色填充**

工具：本轮新增 `out/analyze_shot.py`（区域 R/G/B 的分位数与标准差）。

| 区域 | 像素数 | 结果 |
| --- | --- | --- |
| 门（被白色覆盖的中央大块） | 41 600 | R/G/B 的 **p5~p95 只差 0~1 个灰阶**，**stdev=1.1** |
| 手枪（被红色覆盖） | 12 174 | p5~p95 约 14 个灰阶（边缘抗锯齿带来的抖动） |

**stdev=1.1 = 这一大片 4 万像素几乎是同一个颜色**（门本身的纹理、光照、透视一概不存在）。

⇒ **40%(0x66) 与 100%(0xFF) 在画面上逐像素相同** ⇒ 渲染器**不消费**这个 alpha 字节
⇒ v4.20 的方向本身就错了（docs/19 §二 里「alpha 是否被消费尚未证实」的**风险项被实测证伪**）。

## 三、定性：引擎用「基色 alpha=0」表示**不填充**

回头看引擎自己的数据（离线 dump 配色块 `0x5919A88` + 运行期日志）：

| 状态 | 基色（+0x80）原值 | 含义 |
| --- | --- | --- |
| 0 Generic（武器用） | `0x003EADF2` | **alpha=0** |
| 1 Scanned（防具用） | `0x00B3C1EF` | **alpha=0** |
| **7 TargetScannable** | `0x00000000` | **全 0 —— 原版扫描仪扫「可扫描目标」用的状态** |
| **8 TargetScanned** | `0x00000000` | 同上 |

**原版扫描仪扫物品时（state 7/8）描边基色就是 0** —— 也就是**不填充**，
画面上只有脉冲色（轮廓）。这正是「原版扫描时物品材质看得见」的原因。

而 v4.19 为了让颜色「画得出来」把 state 0/1 的基色 alpha **从 0 补成 0xFF**
（旧注释：「不补就画不出来」—— 这是**未经实测的推测**）⇒ **亲手点亮了「填充」**，
这就是 v4.19 起「覆盖太深、盖住材质」的**唯一**来源。

**时间线自洽性检查**（四条全对上）：

| 版本 | 基色 alpha | 用户反馈 |
| --- | --- | --- |
| ≤ v4.18 | 0（保留原值） | 只抱怨「颜色分不清」，**从没抱怨盖住材质** |
| v4.19 | **0xFF（补的）** | **「覆盖太深，完全盖过材质」** |
| v4.20 | 0x66 | **「没起作用」**（非 0 即填充；具体值被忽略） |
| v4.21 | **0（不填充）** | ← 本轮 |

## 四、v4.21 改动

| # | 改动 | 说明 |
| --- | --- | --- |
| ① | `Config::noFill`（默认 `true`） | 「不填充」总开关 |
| ② | `WriteColorOverrides`：基色（+0x80）写 **`RGB + alpha=0`** | 脉冲 High/Low 照旧（彩色轮廓 = 类别色） |
| ③ | `noFill=0` 时保留旧逻辑 | `patchChannel` + 「alpha=0 补 0xFF」兜底（= v4.19/v4.20 行为，可一键回退） |
| ④ | `colorAlpha` 默认值全改 0 | v4.20 给三类设的 102 已无意义；该键现在**只作用于脉冲（轮廓）** |
| ⑤ | 日志 | 新增 `config: noFill=…`；每行覆盖日志带 `写为 #RRGGBB + alpha=0（不填充：物品材质透出）` |
| ⑥ | INI | 新增 `NoFill=1` + 重写相关说明段（旧 `AlphaXxx=102` 段整体替换） |
| ⑦ | 版本 | DLL `4.20.0` → **`4.21.0`**；MO2 / N 网公开版 `1.7.2` → **`1.7.3`** |

**副作用（如实记录）**：

- 被覆盖的**所有类别**（不止门/武器/防具）都改为「轮廓」，观感更统一；
  想恢复「颜色铺满」就把 INI 里 `NoFill` 改成 `0`（全局）。
- 原版手持扫描仪在**同一状态**上的描边也会跟着变成「轮廓」——本来就共用同一张配色块
  （docs/18 §四 已记录该副作用）。
- 颜色本身不变（调色板与 v4.19 相同），区分度不受影响。

## 五、二进制级验证（新 DLL）

`tools/re/symfind.py`（源码行 → RVA）+ `tools/re/disasm.py`：

```
00029648  cmp byte ptr [rip + 0x7ea59], 0        ; g_cfg.noFill
0002964F  je 0x29659                              ; =0 → 旧逻辑（填充）
00029651  mov dword ptr [rcx + 0x80], edi         ; ★ =1 → 基色直写 RGB（edi 高字节=0 ⇒ alpha=0）
00029659  …（旧逻辑：or 0xFF000000 兜底补不透明）
```

⇒ 「不填充」确实落在基色（+0x80）上，且是**直写**（不是读-改-写）。

## 七、验收点（下一次进游戏）

1. 启动日志出现：
   ```
   config: noFill=1 -> 描边基色（+0x80）写 RGB + alpha=0（不填充：只有彩色轮廓，物品材质透出（v4.21 默认））
   ```
2. 9 行 `outline colors: state=N 覆盖为 #RRGGBB <- 类别…（描边基色原值 0x… -> 写为 #RRGGBB + alpha=0（不填充：物品材质透出）；…）`
   ＋ 一行 `已在管理器创建之前写入 9 个状态的覆盖色`。
3. ★★ 肉眼（本轮核心）：
   - 走到**门**前 / 看地上的**武器**、**宇航服**：**能完整看见物品本身的材质与轮廓**，
     颜色（红/品红/白）落在**轮廓/脉冲**上，仍然一眼可辨；
   - 其余类别（弹药亮绿 / 笔记黄 / 资源紫 / 容器橙 / 设备青 / 杂项蓝）同样「轮廓化」。
4. 觉得「轮廓太淡、东西不够醒目」⇒ INI 里 `NoFill=0` 恢复「实心填充」（重进游戏生效，不用换 DLL）。
5. 不回归：F8 / 扫描仪自愈 / 展示柜拿空熄灭 / 换场景不崩 / 活人一个都不亮。
6. ★ 若「轮廓完全看不见了」（极端情况：脉冲色也被引擎忽略）⇒ 把 `NoFill=0` 的结果与
   `renderer params[...]` 那几行发出来，我们改走「降低颜色亮度」那条路（docs/19 §二 备选①）。

## 八、可复用经验

1. **「写进去」≠「被消费」——两个都要证据**。v4.20 的日志（表、参数块都有 a=66）只证明了
   前者；**后者只能靠画面上量**（本轮 = 区域像素 stdev）。
2. **量化截图要选「大片纯区域」并看分位数**：`p5~p95` 差 0~1 个灰阶这种数字一出来，
   「是不是填充」当场定论，比反复问用户「变没变淡」高效得多。
3. **引擎的数据自己会说话**：`state 7/8 的基色 = 0x00000000` 就是「不填充」的官方用法；
   **和引擎保持一致比自创做法安全**（v4.19 的「补 0xFF 才画得出来」是推测，代价是三个版本）。
4. **推翻旧结论时要给出可判定的新判据**：本轮的 ①②③（日志 + 像素 + 二进制核对）
   任何一条不成立，结论就该重估。
5. **回退开关要和改动一起进去**（`NoFill=0`），这样「下一轮实测」不需要重新编译。
