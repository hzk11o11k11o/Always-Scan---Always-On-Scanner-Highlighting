★ 关闭分支的实现细节（为什么是「三件事」）：① 不建 `SizeLimitedFileSink`（不创建 / 不打开文件，
旧日志文件保持原样 —— 不删不追加）；② `logger->sinks().clear()`（清掉一切 sink，包括 MSVC 调试输出）；
③ `logger->set_level(spdlog::level::off)`（之后所有日志调用零输出、开销降到一个 level 比较）。
只做其中一两件都不算「完全关闭」（只不建文件 ≠ 不写；只关 level ≠ 不建文件）。

## 五、经验

- **「配置项」语义升级要连同内置默认值一起改**（否则「INI 缺失 / 手动安装」的用户仍拿到旧行为 ——
  与需求相反）；本次把内置默认也改成 0，与「公开版完全关闭」口径对齐；
- **「关闭日志」是三个动作**（不建文件 + sink 清空 + level off）—— 缺一个都可能留下输出路径；
- **历史文档条目「保留原文 + 加指针」**（README / description 里 (14) 的「default 1」是当时事实，
  不重写历史，只注明「见 (16)：现在发的是 0」）；
- **发布包的「公开版口径」要能在包内验收**（本次包内 INI 的 `LogMaxMB=0` 与模板逐字节一致 ⇒
  一眼可证「打包脚本的模板覆盖机制」在干活）。
