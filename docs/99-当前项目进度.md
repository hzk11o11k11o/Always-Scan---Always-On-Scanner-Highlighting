> `搜空: empty=0 notEmpty=0 unknown=0 null=0 shapeBad=0 **invOff=未标定**` +
> `inventory calibration: 仍在攒样本（rounds=40 checks=160 votes=+0xA0:160 / +0xA8:0
> **strong=0/0** bad=0/160）` ⇒ **判空链路的前置标定一次都没成功** ⇒ `g_invOff == 0`
> ⇒ `Rescan` 里判空整段被跳过 ⇒ 所有容器 / 尸体照常亮（= 用户看到的现象）。
> ★ 反证（**同一 DLL** 的上一局 17:57~18:34）：`off=+0xA0 ok=4 strong=1 … -> 搜空判空**启用**`、
> `搜空: empty=225 notEmpty=0` ⇒ 判据本身没问题，**是本局标定沉默**。

> **★ 根因（读代码即可确认）**：`CalibrateInventory()` 的采样循环每轮都 `i = 0` 起 ——
> 40 轮采到的是**同一批引用**（引用数组前 4 个 CONT / ACHR）；用户那一局那 4 个恰好都是
> **空容器**（`size==0` ⇒ 只算弱票）⇒ `strong` 永远 0 ⇒ 采纳条件
> `votes>=3 && bad<=2 && **strong>=1**` 永不满足（`bad=0` 说明偏移/内存读都没问题）。
>
> **修法（只改 `plugin/src/AlwaysScan.cpp`；ESM / Papyrus / INI 键未动）**：
> ① **轮转采样**（`State::invCalibCursor`：游标每轮往后走、扫到尾巴回数组头）⇒ 场景里
> 的容器 / ACHR 都能被采到；② **玩家自己当一个样本**（背包必然有东西 ⇒ 正常第 1 轮
> 就拿到强样本；玩家样本**只投赞成票**、形状不过**不计 bad**，避免把 `bad<=2` 闸门卡死）；
> ③ **末轮样本留痕**（`invLastSample[4]`）+ `仍在攒样本` 日志打出样本明细
> （`[0] ref=… base=… CONT size=0 obj=00000000`）⇒ 下次万一还攒不到可一眼分清
> 「采到空容器」还是「读不出形状」。★ **底线不变**：仍然要求 ≥1 个强样本才采纳。

## 踩坑记录（精选 —— 完整版见 git 历史）

1. **`.pas` 必须纯 ASCII，且不能出现花括号** —— UTF-8 中文注释会被按 GBK 解码、字节撞进语法；
   Pascal 的 `{ }` 注释在**第一个** `}` 处结束。`build-sas.ps1` 现在**预检并拒绝**
   （含 `>127` 字节 / 花括号的 `.pas` 直接报错）。
2. **`std::min/std::max` 与 `Windows.h` 的 min/max 宏冲突**（`error C2589`）
   → 在 `PCH.h` 最顶部定义 `NOMINMAX`。
3. **commonlibsf 的 `TESObjectCELL` 偏移是错的（整体 +8）** —— 头文件注释里的偏移
   ≠ 编译器算出来的偏移；`static_assert(sizeof(...))` 只保证尺寸、**保证不了成员位置**。
   凡是「信头文件偏移去解引用指针」的地方都要先校验。
4. **「形状校验」比「猜偏移」可靠**：最坏结果也只是「不发光」，而不是崩游戏。
5. **RTTI 的 `REL::ID` 查出来的是 TypeDescriptor，不是 vtable**（v4.11 栽过）——
   正确求法只有 `COL → TypeDescriptor` 链或「构造函数里写这个指针的那条指令」；
   已固化为 `tools/re/vtable_owner.py`。附带：多重继承里同一个类的所有 vtable 的
   COL 都指向同一个 TD ⇒ **对象偏移才是判据**（再用「首槽析构 thunk」交叉校验）。
6. **「安全阀」的阈值本身也要被核对，并且阀要留「阀自己错了」的日志**
   （v4.11 就是 40 条 WARN 破的案）。
7. **取证日志的额度要「按名字均摊」**：全局 48 条在长会话里必然烧光 ⇒ 改成
   「每个名字头 3 条必记」，任何一局都能看到全貌。
8. **★ 写进表 ≠ 生效**（v4.18）：颜色是「参数表的静态数据」，落地要经过
   「管理器创建 → 交给渲染侧」；管理器只在创建那一刻读表 ⇒ 覆盖必须写在创建之前。
