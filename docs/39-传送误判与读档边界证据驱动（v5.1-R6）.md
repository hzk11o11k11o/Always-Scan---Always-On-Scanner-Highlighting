# 39 · 「传送后已扫描物品变青」——读档边界改为**证据驱动**
（DLL v5.1.0 订正 R6 / 公开版仍 `2.0`）

> 建立：2026-09-27（接 `docs/38`）。
> 触发：用户报告（原文）——
>
> ```
> 传送切换地图后，出现了已扫描物品变成扫描前青色的问题，开启扫描仪再关闭又变回绿色
> ```
>
> 承接：`docs/38`（v5.1.5 / R5：读档 = 存档边界 + 星球作用域）。
> **一句话结论**：R5 把引擎的 `TESLoadGameEvent` 当「读档」的**无条件**边界 ——
> 而这个事件**不只在读档时发**（用户那次的「传送切换地图」就触发了它：日志里被记成
> 「读档 #2」）⇒ 一次传送就把**真绿**当成假绿作废了（丢掉 21 条 / 证伪 8 个 base）。
> 修法 = 事件只当**候选**，复核**延后到世界稳定**后才做，且**一个 base 都证伪不了就不作废**
> （= 判定「传送 / 读同一存档」）；另外复核**跳过「只见证于别的世界空间」的 base**。

### 1.2 为什么「证伪 8 个 base」是**假证伪**

* 那 8 个被证伪的 base 就是 09:51~09:52 刚被**引擎亲手画绿**的那批矿脉
  （0x25232B / 0x25323A / 0x270033 / 0x75CAD / 0x270039 / 0x27002C / 0x25321C / 0x27002F）——
  引擎画 4/5 = 它自己判定「已扫描」⇒ 这些绿**不可能是假绿**；
* 用户 09:55:59 一举扫描仪，引擎又把同一批 base 画成 4/5（1.1 表最后一行）——
  **勘测数据没有倒退**，那次「证伪」只能是复核本身的问题：
  1. 复核发生在「载入画面关闭」那一瞬间（v5.1.5 的 `ProcessFloraSaveLoad` 直接内联在
     Tick 的载入分支里）——换世界空间时勘测数据 / 上下文可能还没就绪；
  2. 复核用的资源链查询带**当前上下文**（见 §1.3）——记忆里属于**别的世界空间**的 base
     在它上面查，很可能答「没扫描」。

### 1.3 离线核对（本轮新做）

| 核对项 | 方法 | 结论 |
| --- | --- | --- |
| 「读档事件」有几个发送点 | `python tools/re/func.py callers 0xB9A260`（`TESLoadGameEvent::GetEventSource`，ID 64149） | **13 个调用点**（0x6C4FE0 / 0x6C5072 / 0x70093B / 0x700BF7 / 0x1787AB2 / 0x178A12B / 0x1845EEB / 0x188266C / 0x189BB55 / 0x20DD119 / 0x20DDF9D / 0x2175D45 / 0x2175DE1）⇒ 这个事件**本来就不是「读档专用」**（读档不可能有 13 个入口；用户日志也实证了传送会发） |
| 资源链查询的作用域 | `python tools/re/disasm.py … 0x1597A50`（`IsResourceScanned`） | 函数只有一个参数（`BGSResource*`）但内部有**上下文**：先取全局表 + 一个 **16 位常量** 拼 key 查（`0x7B7D60`，key = `(word<<48)|(formID<<16)`，`0x7B7DE0` 处读 `[rip+0x5A29FAD]`，该常量**零写入** = 编译期常量）；第二条路用**玩家对象 `[obj+0x28]` 的上下文 ID**（经 `0x347170`，dl=0x81）再查一遍。⇒ 「换个世界空间 / 星球，同一个资源的答案可能不同」是**引擎结构上就可能发生**的事 —— 所以复核必须排除「只见证于别的世界空间」的 base |

### 1.4 为什么「延后 4 秒」是必要的

* v5.1.5 的复核时点 = `ResetForNewScene` 之后**同一帧**（载入画面刚关）；
* 那一刻引擎的勘测数据 / 玩家上下文是否就绪没有保证（本局 09:55:51 的 8 个假证伪
  就发生在这一瞬间）；
* 延后到「载入画面关闭 + 4 s 且没有新的载入」后，世界已稳定（本 MOD 的扫描静置
  只需 2 s，4 s 更宽裕）—— 复核实测也正好在这一档里跑（见 §三 验收 ②）。

**行为变化（给用户的三句话）**：

1. **传送 / 换地图不再把已扫描的东西变青** —— 读档事件只当候选，复核后「一个资源都证伪不了」
   就认定是传送（勘测数据没倒退）⇒ 记忆保持原样（不推进作用域、不清物种表、不丢条目）；
2. **真读回更早的存档**仍然会把假绿清掉（复核**能证伪**才是真读档）—— 矿脉 / 气泉 / 液池
   立刻正确，植物的青色代价与 R5 一致（举一次扫描仪即恢复）；
3. 复核**延后 4 秒**（等世界稳定）并且**跳过只见证于别的星球 / 世界空间的资源** ——
   这两条专门挡「换世界空间那一瞬间的假证伪」。

## 四、验收判据（下一次进游戏）

1. 启动日志（逐行核对）：
   ```
   SAS_AlwaysScan v5.1.0 loading（订正 R6：读档边界证据驱动 —— 传送不再误作废 + 复核延后到世界稳定 + 跨世界空间跳过证伪）
   config: floraLoadBoundaryEvidence=1 -> 「读档边界」的判定口径：★ 证据驱动（默认）…；复核延后 4000ms …
   ```
2. ★★ **传送场景（本次核心）**：先玩到扫过一些资源（矿脉 + 植物），然后**传送 / 切换地图**
   （含跨星球、进城市等会弹载入画面的传送）⇒
   * 传送后**已扫描的目标仍然是绿的**（不再变青；不需要再举扫描仪）；
   * 日志出现 `flora memory: 读档候选 #N（载入画面关闭）-> 资源链复核 X 个 base：
     **没有一个被证伪** … ⇒ 判定为**传送 / 读同一存档** …`；
   * 统计行 `| 读档边界(★v5.1.6): 事件保留=` 在涨、`推进=` **不涨**。
3. ★★ **真读档场景不回归**：读回一个**更早的存档**（那次存档里没扫过某些资源）⇒
   * 那个存档里**没扫过**的矿脉 / 植物是青的（`链复核: 丢` 出现非 0、`推进=` 涨 1）；
   * 确实扫过的矿脉立刻绿、植物举一次扫描仪后绿（与 R5 的代价一致）。
4. ★ **换星球**：星球 B 上同 species 但没扫过的资源仍是青色（`星球外拒=` 非 0）；
   ★ 复核里「只见证于别的世界空间」的 base 会被**跳过**（统计行 `跳过=` 在涨）。
5. ★ **重开游戏继续玩同一存档**：本会话第一次读档后，之前扫过的目标（落盘记忆）仍直接是绿的
   （`FloraMemoryScope=1` 的体验不回归）。
6. 不回归：F8 开关 / 扫描仪自愈 / 展示柜（关着也亮、拿空即灭）/ 换场景不崩 / 活人不亮 /
   分组配色 / `引擎状态表: 条目=` 稳定 / 动态场景不卡（`timing3` 的 `卡顿` 与 `最慢一轮 cpu=`）。
7. 回退开关（都不用换 DLL）：
   * `FloraLoadBoundaryEvidence=0` ⇒ 回到 R5 行为（事件即边界，无条件作废）；
   * `FloraMemoryScope=2` ⇒ 最严格（不依赖证据、每次事件都推进）；
   * `FloraSpeciesPlanetScope=0` ⇒ 按物种扩散回到全局（对照用）—— 同时也会让 §二⑥ 的
     「跨世界空间跳过」失效（对照口径）。

## 五、可复用经验（写给下一轮）

1. **「事件 = 语义」是假设，必须验证**：`TESLoadGameEvent` 的名字、commonlibsf 的定义、
   文档里的既有结论（R5 的「快速旅行 / 进门不算」）全都在暗示「它只在读档时发」——
   但 `func.py callers` 一眼就能看到**13 个发送点**（读档不可能有 13 个入口），
   用户日志又实证了传送会发。**新用的引擎事件，先数一遍发送点**。
2. **不可逆操作（丢记忆 / 推进作用域）必须只在「有正向证据」时做**：
   「证伪比证实便宜」的另一半是「**没有证伪就不动手**」——把「事件」降级成「候选」、
   把「结论」交给可证伪的判据（资源链），是这一轮最核心的一步。
3. **复核的时机也是证据的一部分**：同一个查询在「载入画面关闭那一瞬间」和「世界稳定后」
   可能给出不同答案（本轮的 8 个假证伪）。**凡是引擎查询，先问「此刻世界就绪了吗」**。
4. **跨上下文（星球 / 世界空间 / 存档）的查询要带作用域过滤**：
   `0x1597A50` 只有 `BGSResource*` 一个参数，但反汇编里能看到它内部还带
   「16 位常量 + 玩家对象 `[+0x28]` 上下文」—— **参数少 ≠ 无上下文**；
   用「见证时记下的 worldspace」过滤，是上一轮（R5）就建好的数据结构，这一轮直接复用。
5. **统计行要有「证明旧行为错」的那一档**：`事件保留=`（无证伪）与 `推进=`（真读档）
   并排出现，下一次一眼就能判「这次是传送还是读档」；
   用户报告的偶发问题，**日志先分层、再谈修复**。
6. **给每一次「软化」都留回退开关**：`FloraLoadBoundaryEvidence=0`（回 R5）、
   `FloraMemoryScope=2`（最严格）、`FloraSpeciesPlanetScope=0`（对照）——
   三种口径互不覆盖，用户可自救、我们可对照。
