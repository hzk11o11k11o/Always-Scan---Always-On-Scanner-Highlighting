# 00 · 项目总览与技术方案

> 2026-09-16 建立。项目代号 **Always Scan**。

## 一、要解决的问题

原版《Starfield》里，玩家必须**切到手持扫描仪**才能看到物品高亮；而切到扫描仪时
不能开枪、不能用别的工具，很不方便。而且原版只有**屏幕中央那个圆圈里**的东西才会亮。

本 MOD 要做三件事：

1. **不装备扫描仪也能有高亮效果**（核心）；
2. **不受中央圆圈限制** —— 改成玩家周围一个半径（默认 50 米，可配）；
3. **一个快捷键**开关。

## 三、架构

```
┌────────────────────────────────────┐        ┌────────────────────────────────┐
│ SAS_AlwaysScan.dll (C++ / SFSE)    │        │ SAS_Bridge.psc (Papyrus)       │
│                                    │        │                                │
│ 每帧 Tick()（SFSE 永久任务）        │  FLST  │ 每 0.25s Drain()               │
│  ├ 每 200ms 遍历玩家所在 cell       │ ─────► │  ├ 读 OpList / StopList        │
│  │   TESObjectCELL::ForEachReference│ 信箱   │  ├ EffectShader.Play(ref, 90s)  │
│  ├ 距离 + base form 类型白名单过滤   │        │  └ EffectShader.Stop(ref)      │
│  ├ 距离分档挑选（不挤在脚边）        │ ◄──── │                                │
│  ├ 令牌桶限流（稳态 8 条/秒）        │  GLOB  │  └ 进度**只存一份真源**＝GLOB  │
│  └ 差异 → 追加 Play/Stop 请求        │ 游标   │                                │
└────────────────────────────────────┘        └────────────────────────────────┘
```

**为什么「找目标」必须在 C++ 侧**：Papyrus 找东西只能靠
`FindAllReferencesWithKeyword`（实测单次 0.13~0.6 秒、只能覆盖带特定关键词的
base form、结果上限被 Papyrus 数组卡在 128）。原生侧直接遍历 cell 的引用数组，
几千个引用一轮只有微秒级，**无关键词、无上限、无脚本开销**。

**为什么「点亮」还在 Papyrus**：`EffectShader.Play/Stop` 目前只有 Papyrus 暴露
（commonlibsf 里 `EffectShader` 没有 REL::ID）。所以保留一个**极轻**的桥：
它不做搜索、不做判断，只按信箱里的顺序 `Play/Stop`，并把游标写回 GLOB。

## 四、跨语言通道协议（关键设计）

DLL 与 Papyrus 之间**不能直接传引用**（VM 参数编组需要 Object handle + BindObject，
风险高），所以用 FormList 当信箱：

| 表单 | 方向 | 说明 |
| --- | --- | --- |
| `SAS_OpList` (FLST) | DLL → 脚本 | 「该亮」的引用 |
| `SAS_OpCursor` (GLOB) | 脚本 → DLL | 脚本已处理到第几个 |
| `SAS_StopList` (FLST) | DLL → 脚本 | 「该灭」的引用（**只在玩家关掉开关时**用） |
| `SAS_StopCursor` (GLOB) | 脚本 → DLL | 同上 |
| `SAS_Epoch` (GLOB) | 脚本 → DLL | 读档计数器，变化 = 整批重置 |

- **清表条件（DLL 侧）**：`cursor == size`（**相等**，不是 `>=`）才清。
  读档后 GLOB 会回滚成陈旧偏大的值，`>=` 会在脚本还没处理时就把新条目清掉。
- **游标必须早于 Play/Stop 推进**（脚本侧）：`EffectShader.Play` 会把 Papyrus 栈挂起，
  而事件不排队；进度只存在函数返回值里就会「新栈读旧值 → 重复 Play → 栈雪崩 → VM is frozen」。

## 五、视觉层的选择（也是本 MOD 最需要继续推进的地方）

本 MOD 的「扫描仪效果」目前落到 **EFSH（EffectShader）** 上：ESM 里克隆一条原版
`ReconTargetingFXS`（原版「瞄准标记」用的高亮着色器）并改了颜色。
这条路线是**原版自己的机制**（原版 `glowingLootDropSCRIPT.psc` + `CargoDropGlowFXS`
就是同一套），不是自造材质/网格，兼容性好。

> **理想方案（已调研，未落地）**：直接驱动引擎自带的 outline 高亮系统
> —— 它有整套 `Monocle` 分类的 GMST（描边颜色/粗细/脉冲），按
> `Generic / Scannable / Scanned / FullyScanned / Tracked / Bounty / Social /
> Target*` 分状态着色，还有 `HighlightManager` 与
> `GatherHighlightsRenderPass` / `HighlightRenderPass`。
> 详见 `docs/01-原版扫描仪高亮机制调研.md`。真要做进去需要深度逆向渲染层，
> 本 MOD 的 v1 先把功能做出来，视觉层留了替换口（只要改 ESM 里的 EFSH 即可）。

## 六、过滤规则（base form 类型白名单）

| 收 | 不收 |
| --- | --- |
| MISC / BOOK / ARMO / WEAP / AMMO / ALCH / INGR / KEYM / NOTE / SLGM（可拾取）<br>CONT / ACTI / DOOR / TERM / FLOR / MSTT（可交互） | **NPC_ / ACHR / LVLN（NPC 与生物）**<br>STAT（纯场景静态物）、FURN（椅床，太吵）<br>玩家自己、`IsDeleted()`、`IsDisabled()`、不属于本 cell 的 |

改动只需要动 `plugin/src/AlwaysScan.cpp` 的 `IsHighlightableBase()` 一个 switch。

## 七、快捷键

`plugin/src/AlwaysScan.cpp` **每帧轮询 `GetAsyncKeyState`**（只在游戏窗口处于前台时生效），
默认 **F8**，在 INI 里用虚拟键码配置。

> 为什么不用引擎的输入系统：Starfield 的 Papyrus 没有 `RegisterForKey`/`OnKeyDown`，
> 而 commonlibsf 里 `BSInputDeviceManager` 没有头文件、SFSE 的 `InputMap` 只有键码工具
> → 走引擎输入事件源属于「中等风险逆向」。轮询 `GetAsyncKeyState` 是等效且零风险的替代。

## 八、性能与稳定性设计（每条都有前一代项目的实测依据）

| 设计 | 原因 |
| --- | --- |
| 每 200ms 扫一轮，单轮纯内存读（零引擎调用） | 遍历 9000 个引用实测 `iter=0ms` |
| **绝不缓存 `BSTArray` 的 `data()/capacity()`** | 清表可能释放/搬移缓冲，缓存下来就是悬空指针，往那儿写 8 字节 → 延迟 `HEAP_CORRUPTION` 崩溃 |
| 换 cell / 读档走**退役队列**（继续保活 2.5 秒） | 发光集合的 `NiPointer` 是那批 ref 唯一的保活来源；立刻释放会让信箱里未处理的 op 指向已销毁对象 → `Play` 野指针 |
| 只管主线程（`GetCurrentThreadId` 比对） | SFSE 的 `AddPermanentTask` 挂在 `Command_Process` 上，读档期间加载线程也会调它 |
| **令牌桶**限流（稳态 8 条/秒、桶 80） | 密集区（16 米内 1000+ 候选）会让「有新目标就推」变成 20 条/秒直到离开该 cell，主线程被占满 |
| op 只发 Play，**走远不发 Stop**（由 effect 自行过期） | 「一半 op 花在熄灭上」是上一代卡顿的根因；op 与目标集大小解耦 |
| 距离分档（每 2 米一档、每档 6 个） | 「取最近的 N 个」会让目标全挤在脚边（实测 `near=0.3~2.1` 世界单位），玩家一走动全部出局 → op 洪流 |
| 已发光目标排序键 ×0.5（黏性） | 站着不动目标不抖；走动时近的新目标仍能顶掉远的旧目标 |
| 配置项只在启动时读一次 | 避免热路径上的文件 IO |

## 九、构建

```powershell
# 全流程（xEdit 生成 ESM ≈ 4~5 分钟 + Papyrus + DLL + 部署 + MO2 profile）
pwsh -File tools\build-sas.ps1

# 只重编 DLL
pwsh -File tools\build-sas.ps1 -SkipPluginBuild -SkipPapyrusCompile

# 只重编脚本
pwsh -File tools\build-sas.ps1 -SkipPluginBuild -SkipDllBuild
```

★ **必须用 `pwsh`（PowerShell 7）**：`build-sas.ps1` 是 UTF-8 无 BOM，
Windows PowerShell 5.1 会按 GBK 解码，中文路径变成乱码。
