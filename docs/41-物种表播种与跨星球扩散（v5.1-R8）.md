> **一句话结论**：R7 的读档边界**已经不再误作废**（那一局统计行 `作废=0条`），
> 所以这次的青色另有原因 —— 而它在**同一份日志**里：
> ① 6 分钟前在 **A 点本会话亲手扫过**的物种，星图快速旅行到 **B 点**后被
>   **「按物种扩散必须同一颗 worldspace」** 硬拒绝（`星球外拒=37`）⇒ 整批植物青色；
> ② 外景的星球目标引用是**运行时临时引用（FormID `0xFF……`）**，新会话 / 换场景后
>   **同一物种的实例换了 FormID** ⇒ **按引用的落盘记忆根本命中不了**（载入后 `记忆: 命中=2`）。

> **（b）物种表用「作用域内的落盘绿条目」按 base 播种** ⇒ 同 species 的实例
> **不必等玩家举一次扫描仪**就是绿的。

### 1.3 这一局的两条硬结论

1. **引擎的「物种已扫描」知识跨星球生效**：A 点扫过的 species（`0x185489` / `0x1854D8` /
   `0x1854C1` / `0x18547F`），在 B 点（不同世界空间）**引擎自己画绿 4/5** ——
   这正是「按物种扩散」的定义（`docs/35` 已证：引擎知识库是 species 级），
   而 R5 的「必须同一颗 worldspace」把它硬挡成青色 ⇒ **假青**；
2. **`星球外拒` 的语义其实只是「偏离」**：它证明的是「这个 base 的见证记录里没有当前这颗星球」，
   **不**证明「这颗星球上没扫描」—— 引擎已经用画绿回答了这个反例。

### 1.4 为什么「引用级记忆」必然先青后绿（换会话 / 换场景都会发生）

* 外景的星球目标（植物 / 矿脉）是**运行时临时引用**：FormID 落在 `0xFF……` 段，
  **每次（重新）生成引用就换号**。本局的实例是 `0xFF02A7xx / 0xFF0379xx / 0xFF04ECxx / …`；
  而落盘文件里上一会话记的是 `0xFF02A6xx / 0xFF0378xx / …` —— **同一片地方，号不同**；
* ⇒ `floraRefKnow`（引用 → base）命不中，唯一能命中的层次就是**物种（base）**；
* 本局 `flora learn: 记忆保留（369 条引用 / 物种表 13 个 base）` 里的 13 个 base
  全是**本会话**（A 点）见证的 —— 也就是说：**信息其实够**，只是被星球口径挡掉了。

## 二、修法（两处，都在 `plugin/src/AlwaysScan.cpp`）

### 2.1 ① 按物种扩散**不再按星球硬拒绝**（`FloraBaseKnown`）

口径从「必须同一颗 worldspace」改回**引擎口径**（= 全局，跨星球）：

| 情形 | R8 默认（`FloraSpeciesPlanetScope=0`） | R5 旧口径（`=1`，保留） |
| --- | --- | --- |
| 物种表里有这个 base，当前 ref 的 worldspace ∈ 见证列表 | 绿（计数 `跨星球放行` 不涨） | 绿 |
| 物种表里有这个 base，但当前 worldspace **不在**列表 | **绿** + `跨星球放行++` | 拒绝 + `星球外拒++` |
| 读不到 worldspace / 见证时也没读到 | 绿（不收紧） | 绿（不收紧） |

**「不跨存档外溢」这件事改由存档作用域单独保证**（这条本来就是 R5 真正要防的）：
物种表**会话级、不落盘**；每次读档按**游戏时间锚点**剪枝（R7）；落盘记忆只有
**作用域内**的条目才会被播种（②）。⇒ 跨星球扩散不再有任何跨存档通道。

### 2.2 ② 新增 `SeedFloraBaseFromRefMemory()`：物种表**用落盘记忆播种**

```
启动：LoadFloraLearnTable() 读完文件 ⇒ 播种一次
每次读档：TryProcessFloraSaveLoadByTime() 剪枝之后 ⇒ 再播种一次
          （R6 回退路径的「传送 / 读同一存档」分支也顺带播种一次）
```

* 遍历 `floraRefKnow`，只取 `green && FloraEntryInScope()` 的条目（**作用域内**才要），
  按 `base` 新建物种表条目（已存在则把 `days` 往**最早**收，与 `RememberFloraBase` 同口径）；
* 播种出来的条目 `worldspaces` 列表为空（`count = 0`）= 「没有作用域信息」⇒ 不收紧；
* `days` 沿用条目自己的值（旧格式行 = 0 ⇒ 读档剪枝时同样用 legacy 锚）；
* **不落盘**（物种表本来就是会话级表），`FloraMemoryScope=2`（最严格）与
  `FloraLearnPersist=0` 时**不播种**。

### 2.3 日志 / INI / 计数

* 启动行：`config: floraSpeciesPlanetScope=0 -> 按物种（base）扩散的星球口径：★ 引擎口径（默认，v5.1.8）…`；
* 新日志行：`flora learn: 按物种扩散表**播种** N 个 base（启动时载入落盘记忆 / 载入画面关闭；落盘记忆里共 M 条，作用域内才会播种）…`；
* 读档候选行扩写：`…（物种表剪掉 X 个 base；播种后物种表 Y 个 base，本次新增 Z 个）…`；
* 统计行：`| 按物种扩散(★v5.1.8): 命中= 物种表= 新增= **播种= 跨星球放行=** 星球外拒= `；
* INI：`FloraSpeciesPlanetScope` **默认 1 → 0**（模板里补完整背景 / 证据 / 代价说明）；
* 构建指纹（`main.cpp`）：`（订正 R8：物种表用落盘记忆播种 + 扩散不再按星球硬拒绝 —— 传送 / 换星球后已扫描的 species 直接是绿的）`；
  **版本号按用户要求不动**（DLL build 仍是 `5.1.0`、公开版仍是 `2.0`）。

1. 启动日志（逐行核对）：
   ```
   SAS_AlwaysScan v5.1.0 loading（订正 R8：物种表用落盘记忆播种 + 扩散不再按星球硬拒绝 …）
   config: floraSpeciesPlanetScope=0 -> … ★ 引擎口径（默认，v5.1.8）…
   flora learn: 按引用记忆已从落盘文件载入 N 条（…）
   flora learn: 按物种扩散表**播种** M 个 base（启动时载入落盘记忆；…）⇒ 同 species 的实例**不必等举扫描仪**就是绿的
   ```
2. ★★ **继续同一存档 / 载入**：**不举扫描仪**，之前扫过的植物应当**直接是绿的**
   （引擎口径的物种表已由落盘记忆播种）；统计行 `按物种扩散(★v5.1.8): 播种=` 非 0、
   `星球外拒=` **不涨**（默认口径下它只会在 `FloraSpeciesPlanetScope=1` 时才涨）；
3. ★★ **传送 / 换星球（本次核心）**：扫几个资源 → 星图快速旅行到**另一处** ⇒
   已扫描物种**仍是绿的**；`跨星球放行=` 开始有数（= 修复在干活）；
4. ★ **真读回一个更早的存档**：那个存档里没扫过的仍变青（正确）；`作废=` 出现非 0；
   再读回更新的存档 ⇒ 那些条目自动回来（可逆）；播种只会在**作用域内**发生；
5. ★ **换场景 / 战斗 / 走动**不回归：`引擎状态表: 条目=` 稳定、`timing3` 的 `卡顿` 与
   `最慢一轮 cpu=` 正常、展示柜拿空即灭、F8 开关、活人不亮、配色不变。

## 五、可复用经验（写给下一轮）

1. **「修复没生效」和「修复生效了但被另一层挡住」要在同一条日志里分开**：
   本局 `作废=0条` 一眼证明 R7 没失效，于是直接去查**下一个会拒绝绿的判据**
   （`星球外拒=` 在涨）——比重新怀疑读档边界快得多。
2. **判据的「拒绝」语义要和事实对齐**：`星球外拒` 拒绝的是「见证记录里没有这颗星球」，
   而不是「这颗星球上没扫描」；当一个拒绝判据**只见过反例**时（引擎立刻画绿），
   它就是错的判据（`docs/35`/`docs/40` 的同一个教训，第三次出现）。
3. **引用会换号，物种不会**：外景临时引用（`0xFF……`）跨会话 / 跨场景会重新分配，
   任何「按引用」的记忆都只是**快路径**；**跨会话的体验必须靠物种级 + 时间锚点**。
4. **「播种」是把「已经知道的事」变成「马上能用的结论」**：落盘记忆本来就是权威见证，
   缺的只是「按 FormID 找不到」⇒ 换成按 base 播种即可，不需要新的引擎调用、不需要新落盘表。
5. **给每次「放宽」都留回退 + 计数器**：`FloraSpeciesPlanetScope=1` 回 R5 严格口径，
   `跨星球放行=` / `播种=` 两个计数器让下一次日志能直接判定「这次放宽是否在干活」。
