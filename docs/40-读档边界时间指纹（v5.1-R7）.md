# 40 · 「传送后已扫描物品变青」的真正修复：读档边界改用**游戏时间指纹**
（DLL v5.1.0 订正 R7 / 公开版仍 `2.0`）

> 建立：2026-09-27（接 `docs/39`）。
> 触发：用户报告（原文）——
>
> ```
> 传送切换地图后，出现了已扫描物品变成扫描前青色的问题，开启扫描仪再关闭又变回绿色，这个问题还在
> ```
>
> 承接：`docs/38`（R5：读档 = 存档边界）、`docs/39`（R6：读档边界证据驱动）。
> **一句话结论**：R6 拿「资源链复核有证伪」当「读回了更早的存档」的证据 —— 但**载入刚结束时
> 资源链的否定答案是错的**（同一函数对同一资源，80 秒后答案相反）⇒ 一次普通读档就把 132 条
> 记忆删掉（= 用户看到的「已扫描物品变青」）。修法 = **读档边界改用游戏时间指纹**
> （`Calendar::gameDaysPassed`，随存档保存 / 读回）：条目自带「学习时刻」，
> 学习时刻 ≤ 本存档的游戏时间 ⇒ 记忆有效；否则**不在作用域但不删**（可逆）；传送 / 继续
> 同一存档 ⇒ 锚点几乎不动 ⇒ 什么都不作废。

### 1.2 为什么「证伪 9 个 base」是**假证伪**（本轮的决定性证据）

* 那 9 个被证伪的 base 就是记忆里的**矿脉**（`0x25232B / 0x25323A / 0x270033 / 0x75CAD / …`
  —— 与 `docs/39` §1.1 上一次「假证伪」名单高度重合）；6 个「无结论」的是**植物**
  （产出 MISC ⇒ 链本来就不适用）；
* ★ **同一个函数、同一个资源，80 秒后答案相反**：
  * 10:15:38 `0x270033` → 链答「不在勘测数据里」（被证伪、条目被删）；
  * 10:16:56 `0x270033` → 链答「已扫描」（`资源链命中`，写进记忆 + 落盘）；
* ★ **引擎自己的行为**：10:15:48（复核后 10 秒）引擎给 `0x25232B / 0x1854C1 / 0x185479`
  画 4/5（原生绿）—— 引擎的扫描求值（`0x159ED90`）内部用的**就是同一条链的同一个函数**
  （`call 0x1597A50`，见 `plugin/src/AlwaysScan.cpp` 常量区反汇编摘录）⇒ 那时它答「已扫描」。
* ⇒ 结论：**「没扫描」这个否定答案在「载入刚结束」的那段时间没有区分度**
  （链路上下文没就绪时也答「没扫描」）。R6 把它当证据做**不可逆**的删除，
  必然误伤 —— 这就是用户两次报的「已扫描物品变青」。

### 1.3 用户看到的「青」是**删除**造成的（不是作用域规则）

R5/R6 的作用域规则（`FloraEntryInScope`）在**本会话第一次读档**时并不会作废落盘条目
（`epoch == 0` 的条目在 `floraSaveEpoch <= 1` 时算数）—— 本局 `读档 #1` 只把 epoch 推到 1。
真正让 132 条目标变青的是**复核里的删除**（`dropBases` → `erase`）。
⇒ 修法的第一原则：**读档复核不再删任何条目**。

## 二、修法：读档边界 = **游戏时间指纹**（`FloraSaveFingerprint`，默认开）

### 2.1 口径

| 项 | 内容 |
| --- | --- |
| 指纹 | `Calendar::gameDaysPassed`（= 游戏内「已过去的天数」，**随存档保存 / 读回**） |
| 条目 | `floraRefKnow` 每条自带 `days`（**见证时刻**）；落盘行 = `0x引用 0xbase 游戏时间(天)`（**第 3 个字段**） |
| 锚点 | 每次读档候选（载入画面关闭 + 4s、世界稳定）把**本存档的游戏时间**记成 `floraSaveDaysFloor` |
| 判定 | 条目 `days ≤ 锚点 + eps` ⇒ 记忆有效；`days > 锚点 + eps` ⇒ **不在本存档作用域**（不产生绿） |
| ★ 可逆 | **不删任何条目** —— 换一个更新的存档，条目自动回到作用域（R5/R6 是「删掉 + 举扫描仪重学」） |
| 时间线内见证 | 读档后**当场见证**的条目（`epoch == 当前`）不受锚点限制（引擎画 4/5 / 状态==2 / 链命中） |
| 旧格式行 | 没有第 3 字段的落盘行（R6 及更早写的）`days = 0` ⇒ 用 `floraLegacyStampDays`
（= 本会话**第一次**读档的游戏时间）兜底 = R5 的「第一次读档仍然有效」 |
| 物种表 | `floraBaseKnow` 每条带**最早见证时刻** ⇒ 读档时按锚点**剪枝**（不是整表清空） |
| 回退 | `FloraSaveFingerprint=0` ⇒ 回到 R6 链证据路径；**游戏时间读不到**（形状校验没过）时自动回退 + WARN |
| 适用范围 | `FloraMemoryScope=1`（默认）；`=2`（最严格对照）与 `=0`（旧行为对照）不受影响 |

### 2.2 为什么这就治好了用户报的两个问题

1. **传送 / 切换地图（含会发读档事件的传送）**：锚点 = **当时的游戏时间**（没有换存档 ⇒
   游戏时间连续）⇒ 所有 `days ≤ 锚点` 的条目照常有效 ⇒ **什么都不作废** ——
   不再依赖「资源链自己证明自己」这种脆弱证据；
2. **重新读档 / 继续同一存档**：锚点 = 该存档的游戏时间，条目（含旧格式行兜底）都 ≤ 锚点
   ⇒ 全部有效 ⇒ **不会变青**（本局那种 132 条被删的情况不会再有）；
3. **真读回一个更早的存档**：只有「学习时刻晚于那个存档」的条目失效（它们确实不在那个存档里）
   —— 目标变青是**正确的**；而其余条目（包括在更早存档里扫过的）**照常是绿的**
   —— 比 R5 的「一律作废、植物要靠举扫描仪重学」精准得多。

### 2.3 离线核对（本机 1.16.244.0；全部反汇编实证）

| 核对项 | 方法 | 结论 |
| --- | --- | --- |
| `Calendar` 单例 | `tools/re/versionlib.py id 937673` ⇒ RVA **`0x5FDCDF8`** | commonlibsf `RE::ID::Calendar::Singleton` = 同一 ID ⇒ 运行时同一地址 |
| 「单例 = 指针变量」 | `tools/re/func.py rip 0x5FDCDF8` | 24 个引用点，`mov r*, [rip+…]` = 读那个变量（`Calendar**` ⇒ `*` 即 `Calendar*`） |
| `gameDaysPassed` 偏移 | `tools/re/disasm.py … 0x5A73EC` | `mov rcx,[单例] / mov rax,[rcx+**0x30**] / vmovss xmm0,[rax+**0x48**]` ⇒ `Calendar+0x30` = `TESGlobal*`、值 = `TESGlobal+0x48` |
| 交叉验证（另一个字段） | `tools/re/disasm.py … 0x9519FC` | `mov rax,[单例] / mov rcx,[rax+**0x10**]`（`gameYear`）/ `vcvttss2si r8,[rcx+0x48]`，且读不到时兜底常量 **`0x4D` = 77** 与 commonlibsf `Calendar::GetYear()` 的默认值完全一致 |
| 与本地头文件一致 | `tools/commonlibsf-main/include/RE/C/Calendar.h` + `TESGlobal.h` | `gameDaysPassed @ 0x30`、`TESGlobal::value @ 0x48`（后者是本项目 v1 就订正过的偏移） |
| 运行时形状校验（代码里） | `ReadGameDays` | 单例非空 → `gameDaysPassed` 非空可读 → **formType == kGLOB** → 值有限且 > 0；任何一步不过 ⇒ 返回 false（回退链证据路径） |

## 六、可复用经验（写给下一轮）

1. **「否定证据」必须能自证区分度**：一个查询只有在「能区分两种世界状态」时才能当证据。
   `0x1597A50` 在「链路上下文没就绪」时**也**答「没扫描」⇒ 它的否定答案在那一刻
   与真否定**不可区分**（本轮 80 秒后答案相反就是铁证）。**凡是「答否」就动手的代码，
   先问「它答否的时候，是不是因为答不了」。**
2. **不可逆操作要尽量改成可逆的**：同一件事，「删掉条目」换成「移出作用域」之后，
   误判的代价从「要举一次扫描仪才能恢复」变成「自动回来」—— 可逆化本身就是修复的一部分。
3. **存档的「时间」是天然的存档身份**：`Calendar::gameDaysPassed` 随存档保存 / 读回、
   单挑调（引擎自己 24 处在读），比任何间接信号都硬；而**游戏时间锚点 + 条目的学习时刻**
   天然表达「这个事实属于哪个存档的过去」。多分支存档（回读旧档再玩）仍有少量外溢，
   但它比「一律作废」精准得多。
4. **新增引擎调用先离线核对（ID → RVA → 反汇编）+ 用另一个字段交叉验证**：
   本轮两个字段（`gameDaysPassed @ +0x30`、`gameYear @ +0x10`）都指向同一个 +0x48 值偏移，
   而且 year 的兜底常量 `0x4D` 与 commonlibsf 完全一致 —— 布局不可能再错。
5. **诊断也要「不参与判定」**：存档名 / 存档编号这类信息用 `SafeReadMem` + 可打印字符校验
   再进日志，偏移万一不对最坏只是少一行，不影响任何行为。
6. **给每一次「软化」都留回退开关**：`FloraSaveFingerprint=0`（回 R6）、读不到时间自动回退、
   `FloraMemoryScope=2`（最严格对照）—— 三种口径互不覆盖。
