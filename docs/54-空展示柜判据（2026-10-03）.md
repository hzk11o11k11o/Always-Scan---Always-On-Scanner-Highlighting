## 二、根因

展示柜的「拿空即灭」现有**三条**判据（`DisplayCaseReadsEmpty` ①②③），**全部要求
「曾见内容」**：

| 判据 | 成立前提 | 对「本来就空的展示柜」 |
| --- | --- | --- |
| ① 粘性（v4.10） | 此前已被确认拿空过 | ✗ 从未被确认过 |
| ② 同一段打开期（v4.10） | `containerUiOpen` + `lastTpSerial` 段号 | ✗ `ui` 恒 0（ContainerMenu 事件不存在，v4.13 已实证） |
| ③ 兜底（v4.13，v4.14 默认关） | 打开过 + **读到过内容**（`sawContentInSession`）+ 连续空 400ms | ✗ `sawContentInSession` 恒 false（从来就没有内容）；且默认关 |

而**本来就空的展示柜**（EMPTY 版预设 / 被拿空过的）：

- 关闭状态下库存 `size=0`（内容不投影 —— v4.9 的机制，正常）；
- **打开状态下也没有投影条目**（`tpS=0`，逐帧观察 2.4 秒 × 60fps 一次都没读到 `kTemporary`）；
- 自然也没有任何物品事件。

⇒ 三条判据一条都不可能成立，判决永远停在「内容未知 ⇒ 照常亮」（v4.9 的口径），
**永远不熄灭**。这就是用户看到的「空了却还在高亮」。

## 三、修法（只改 `plugin/src/AlwaysScan.cpp` + `main.cpp` 注释/加载行 + INI）

**新增第 ④ 条判据「空箱判据」**（`DisplayCaseReadsEmpty`）：

```
快速面板**为这个 ref 打开过**（quickOpenMs != 0，per-ref 事件证据）
∧ 这一段打开期里**从头到尾没见到内容**（!sawContentInSession）
∧ **没收到过拿走事件**（!sawTakeEvt —— 收到过 ⇒ 箱里曾有东西 ⇒ 交给记账）
∧ 连续读到空、且空窗口起点在打开之后（emptySinceMs != 0 && >= quickOpenMs）
∧ 距打开事件已 ≥ DisplayCaseEmptyNoContentMs（默认 2000ms）
⇒ 判「空」⇒ 粘性熄灭
```

**为什么 N = 2000ms**：面板打开后引擎把内容投影进库存需要 **0.4~0.7 秒**（v4.14
实测）⇒ 2000ms = 3 倍余量；「有内容的箱子」到这个时间点**必然**已读到内容 ⇒ 不会
误灭。`DisplayCaseEmptyNoContentMs=0` 可关（退回 v4.14 行为）。

**为什么判据必须带 `quickOpenMs` 前提**：没有打开事件（用户从没打开过）⇒ 没证据
⇒ 照常亮（保住 v4.9 的「关着的（有内容的）武器箱也要亮」）。

**实现细节**：

1. `DisplayCaseReadsEmpty` 返回值从 `bool` 升级为**原因码**（`kDcEmpty*`）——
   日志文案精确到判据（原来调用点用 `quickOpenMs && !sawTakeEvt` 猜原因，
   会把新判据记成旧兜底）；`MarkDisplayCaseEmptied` 的 `a_fallback` 参数
   同理换成 `a_whyCode`，驱动「兜底 / 空箱」两个诊断计数。
2. 新计数 `displayCaseEmptyNoContent`（窗口内）→ 统计行 `空箱判空=`（紧跟
   `展示柜拿空=`）；日志 `display case emptied (空箱（打开后一直无内容）) [why=4]`。
3. 新 INI 键 `DisplayCaseEmptyNoContentMs`（默认 2000，0 = 关，钳制 0~60000）；
   启动日志那条 `config: containerLootEvents=…` 追加 `displayCaseEmptyNoContentMs=`
   与「空箱判据 = 开/关」。
4. `main.cpp` 加载行追加「★★★★ 订正 R15」识别标记；构建脚本版本历史补记。

**★ 已知的唯一误灭面（如实记录，极窄且可自愈）**：**有内容**的箱子被「打开后不到
0.7 秒就关掉」—— 投影还没建立就被关闭 ⇒ 被判成空箱；**再打开它一次**（投影出现，
`NoteDisplayCaseOccupied`）或往里放东西（put 事件清粘性）即自动恢复。
概率极低（要在装填期 0.7 秒内完成「打开 + 关闭」两次输入）。

## 六、经验

- **「曾见内容」型判据必须有补集**：三条判据都在问「有东西的箱子拿空了吗」，
  没人问「这箱子本来就没东西吧」⇒ 空集永远落不到任何分支。**加判据时先问：
  这个判据的补集谁负责？**
- **事件信号的价值在「前提」而不是「内容」**：`QuickContainerOpenedEvent` 只告诉我们
  「用户打开过它」，但足以把「打开后一直无内容」变成一条可判定的证据（投影装填期
  0.4~0.7 秒是 N 值的标定依据）。
- **日志原因码 > 布尔**：调用点猜原因的写法（`quickOpenMs && !sawTakeEvt`）在新判据
  出现的第一天就会说谎；判决函数直接返回原因码，文案与计数都从它派生。
