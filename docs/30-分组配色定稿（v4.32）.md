# 30 · 分组配色定稿（DLL v4.32.0 / 发布版 1.8.0）

> 建立：2026-09-26。触发：用户新增需求文件 `颜色分类.md`（工作区根目录）+
> 一句话指令：「**根据刚才的讨论，这个分类是很安全的效果，按照这个改动**」。
>
> 需求原文（`颜色分类.md`）：
>
> ```
> # 按以下物品栏分类，将物品赋予不同颜色：
> - 红：武器、投掷物、太空服、背包、头盔、服饰
> - 橙：容器、尸体
> - 紫：笔记、资源
> - 绿：弹药、救援
> - 白：门
> - 青 / 绿（原版）：星球上没扫过/已扫过的资源（矿物、植物）
>
> # 注意事项
> - 杂项还是原版扫描仪的颜色
> - 生物、NPC在扫描仪里的效果不动，保持原版
> ```

一句话结论：**只并组、不新增** —— 「太空服 / 背包 / 头盔 / 服饰」并进
「武器 / 投掷物」的**红组**（state 10）、「笔记」并进「资源」的**紫组**（state 3）；
其余一律不动。覆盖槽位仍是 **2/3/6/9/10 五个**、覆盖色集合一字未变、
**state 0/1/4/5/7/8 依旧一个字节都不写** ⇒ 这就是「很安全」的全部原因。

## 二、为什么这轮「很安全」——槽位账本

v4.30（归还 0/1）之后，全表 11 个槽位的占用是**硬约束**（docs/28 §五.3）：

| 槽位 | 引擎用它画什么 | 能不能借 |
| --- | --- | --- |
| 0 / 1 | 通用引用（**含活人 NPC**，远 / 近） | ❌（v4.30 归还，写 = 行人变色） |
| 4 / 5 | **已扫描**的星球目标（远 / 近）= 绿 | ❌（v4.24 归还） |
| 7 / 8 | **未扫描**的星球目标 = 青脉冲 | ❌（v4.22 归还） |
| **2 / 3 / 6 / 9 / 10** | FullyScanned / Tracked / **从不写** / TargetFullyScanned / 罕见条件 | ✅ **可借（就这五个）** |

本轮需求要 6 组可见颜色（红 / 橙 / 紫 / 绿 / 白 + 杂项原版蓝）——**恰好**装进这五个槽位，
因为其中三个槽位是「免费」的：

1. **9 的原生色本来就是橙**（#FFAA00）→ 容器 / 尸体照旧借 9；
2. **10 的原生色本来就是红**（#FF0000）→ 装备组借 10；
3. **2 的原生色就是杂项要的蓝**（#1F8EE2，写的就是原值）；
4. 「弹药 / 救援 = 绿」不需要新槽位——它继续借 **5** 且**不覆盖**（引擎原生绿）；
5. 真正占「覆盖预算」的只剩 **3（紫）、6（白）**——而这两个槽位 v4.31 就已经在覆盖了。

⇒ **改动面 = 两个类别的 state 字段 + 两个 colorOverride 字段**（外加默认表与日志），
没有新槽位、没有新覆盖、没有新的引擎交互面 —— 因此**风险为零**：
唯一可能被引擎写到的槽位（3 / 10）本来就被覆盖着，引擎行为不会因为「多两个 MOD
类别并进来」而改变；0/1/4/5/7/8 一个字节都不写 ⇒ NPC（v4.30）与星球目标
青 ↔ 绿（v4.22 / v4.24 / v4.28）全部不回归。

★ 同时，v4.31 里「服饰品红 / 笔记黄**让位**」的妥协**就此取消**：
本轮不再需要任何人让位（换组不换色）。

## 六、可复用经验

1. **「并组」是零风险改动，只要组内共享同一个已被覆盖的槽位** —— 把两个类别
   指到同一个 state、给同一个颜色，等于**不动引擎任何状态**地完成了「新增一种
   分类观感」。判断标准：改动前后「写出的槽位集合」与「每个槽位的最终颜色」
   完全一致 ⇒ 引擎侧行为逐字节不变。
2. **先数「必须存在的颜色」再动槽位**（v4.31 的账本）：六组颜色里三组是
   「原生即目标色」的免费色（9 橙 / 10 红 / 2 蓝），另有 5 号原生绿可白拿
   ⇒ 真正吃覆盖预算的只有 3 与 6 两个 —— 需求的「五色 + 白」其实是
   「两覆盖 + 四免费」。**先查原生色表，再谈借槽**（docs/29 §六.2 的同一条）。
3. **用户给的「物品栏分类」本身自带分组语义**：装备类（武器 / 投掷物 / 护甲 /
   服饰）在同一屏里不会同时大量出现，同色反而更像「一套」；而「搜刮（橙）/
   知识材料（紫）/ 消耗（绿）/ 通路（白）」四组各自都可一眼分辨 —— 分组设计
   比「每类一色」更符合实际使用场景。
4. **需求文件（`颜色分类.md`）比聊天记录更可靠**：它固定了「哪类是哪色」的
   权威口径，实现时逐条映射成 `Category → state` 表即可，验收也能逐条对照。
5. **部署窗口 = 游戏关闭时**：MO2 的 usvfs 会把 Data 映射进游戏进程，
   `esm` / `dll` 在游戏运行期间被锁（Copy-Item 直接报 sharing violation）——
   构建流水线要在「先确认 `Get-Process Starfield` 为空」之后跑。
