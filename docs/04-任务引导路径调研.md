# 04 · 任务引导路径（地上那条线）调研

> 2026-09-16 建立。起因：v2 实测「高亮对了，但地上没有任务引导线」。
> 游戏版本：Starfield 1.16.244.0。

## 一、它不是 outline 高亮系统的一部分

v2 把描边拉起来了（`docs/03`），但引导路径**完全没有出现**，因为它是另一套东西：

- outline 高亮 = 「引用 → 状态 → HighlightManager → 渲染器」；
- 引导路径 = **挂在玩家身上的一个魔法效果**，由它自己算路径、自己画線。

## 二、★ 定位到的具体形态（这次的关键产出）

手段：直接在 `Starfield.esm` 里搜 EDID 明文（`tools/re/esmstrings.py`），
再用「EDID 子记录 → 往前 24 字节的记录头」反查 FormID（`tools/re/esmformid.py`）。

| EDID | 签名 | FormID | 备注 |
| --- | --- | --- | --- |
| `ScannerGuideEffect` | MGEF | **0x0003CC95** | ★ 画路径的那个魔法效果 |
| `SpellScannerGuide` | SPEL | **0x0003CC96** | ★ 装着上面那条 MGEF 的法术（两个记录紧挨着） |
| `ArtifactPowerPrecognition_GuideEffect` | MGEF | - | 「预知」能力的同类效果，说明 GuideEffect 是通用能力 |
| `HandscannerGuideSpellDO` | DFOB | **0x00112B0B** | 引擎用来取到 `SpellScannerGuide` 的默认对象 |
| `ScannerGuideHazard` | - | - | 危险物路径（另一支） |

相关的 **INI / GMST**（都在 `:Magic` / `:Interface` 分类，另有 `Guide*` 短名版本）：

```
fMagicGuideSpacing / GuideSpacing
iMagicGuideWaypoints / GuideWaypoints
sMagicGuideNoPath    / GuideNoPath        ← 置 1 大概就是「不画路径」
sMagicGuideNoMarker  / GuideNoMarker
fMagicGuideUpdateFrequency / GuideUpdateFrequency
GuideTargetRadius / GuideEffectPathingRadiusMult / GuideEffectAllowIncompletePaths
GuideAlignmentRayLength / GuideAlignmentZOffset / GuideHazardsPerUpdate
GuideEffect_SecsUntilFadeOut:Interface
```

**没有任何 Papyrus 脚本引用它**（把 `Data\Scripts\Source\**` 全搜了一遍
`ScannerGuide` / `HandscannerGuide` / `GuideSpell` = 0 命中）⇒ 加/摘法术这件事
**是引擎 C++ 侧做的**（扫描期间从 `HandscannerGuideSpellDO` 取法术加到玩家身上，
不扫描就摘掉）。这正是「不装备扫描仪就没有路径」的原因。

## 三、本 MOD 的做法（v2.1 已实现）

既然路径的渲染是那条 MGEF 自己的事、**不需要扫描模式**，那就自己把法术加上：

- `scripts/SAS_Bridge.psc` 新增 `SyncGuideSpell()`，在既有的 0.25 秒心跳里调用：
  - 玩家没有 `0x0003CC96` → `AddSpell`；
  - 有法术但 `HasMagicEffect(0x0003CC95)` 为假（说明它是「发射即忘」型且已过期）→
    `RemoveSpell` + `AddSpell` 重新点火；
  - 是 Ability 型的话第二个分支永远不触发，加一次就一直在。
- 没有改 ESM、没有加新属性 —— `Game.GetForm(formID)` 直接取原版形态，
  所以这条链路只要 Papyrus 编译通过就能跑。

**已知取舍**：

- 目前**与 F8 开关无关**（F8 只管描边）。做成联动需要 DLL 写一个状态 GLOB
  （最省事的做法是给 ESM 加一个 GLOB，走和「引导路径」一样的 `SyncGuideSpell`
  读取 —— 见下面 TODO）；
- 只要存在「正在追踪的任务目标」，路径就会一直画（原版是只有举着扫描仪才画）。
  这正是本 MOD「一直开扫描仪」的定位；如果嫌吵，可以把它做成 INI 开关。

## 四、还没验证的（下次实测重点）

- [ ] 加上 `SpellScannerGuide` 后地上到底有没有线（**最关键的未知**：
      引擎的路径渲染是否还受「扫描模式 / Monocle HUD」门控）；
- [ ] 如果画出来了：线是画向「当前追踪的 quest 目标」还是「准星指向」；
- [ ] 如果没有：下一步查 `HandscannerGuideSpellDO` 的引用者（`tools/re/func.py rip`
      找 DFOB 地址的 RIP 引用），看引擎是在哪个函数里 AddSpell 的、还做了什么别的准备；
- [ ] 与 F8 联动（加 `SAS_On` GLOB，DLL 在 `SetOn` 里写值，脚本读它决定加/摘法术）。

## 五、工具

| --- | --- |
| `tools/re/esmstrings.py` | 在 .esm/.esp/.esl 里搜 ASCII 子串（EDID 全是明文），打印命中处上下文的可打印串 |
