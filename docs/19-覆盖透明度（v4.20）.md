# 19 · 覆盖太深 → 半透明（DLL v4.20.0 / 发布版 1.7.2）

> 建立：2026-09-25。触发：用户实测（附截图）——
>
> ```
> 颜色分类起效了，但有个小问题，就是颜色覆盖太深了，完全盖过了物品本身材质，
> 连物品本身长什么样都不知道了，弄浅一点，主要是门，武器，防具
> ```
>
> 截图内容：近处的**门**是一整片米白（`#FFFFFF` 覆盖），地上的**手枪**是一整块
> 粉红（`#FF2E2E` 覆盖）——两者都看不出任何材质细节。

本轮只做一件事：**给「颜色覆盖」加一个可按类别调节的「不透明度」（alpha）**，
默认把用户点名的三类（门 / 武器 / 防具）调成 **≈40%**，让物品本身的材质透出来。

---

## 一、先看现有的写入逻辑：alpha 一直是「保留引擎原值」

`WriteColorOverrides()`（v4.19）对每状态写三处，dword 布局 `0xAARRGGBB`：

| 位置 | v4.19 的写法 |
| --- | --- |
| `+0x00` 脉冲 High | 只换 RGB，**alpha 原样保留** |
| `+0x20` 脉冲 Low | 同上 |
| `+0x80` 描边基色 | 只换 RGB；**alpha = 0 时补 0xFF**（state 7/8 那种没初始化过的槽） |

也就是说：**覆盖强度（alpha）完全由引擎那个状态原本的值决定**。而 2026-09-25 的
`outline colors[install]` 日志（用户的真实会话）证明这些原值**各不相同**：

```
state= 0 weapon   描边基色原值 0x003EADF2  -> alpha=0 已补 0xFF   （脉冲 High 原值 0xFF3EADF2）
state= 1 apparel  描边基色原值 0x00B3C1EF  -> alpha=0 已补 0xFF   （脉冲 High 原值 0xFF72E8FF）
state= 2 loot     描边基色原值 0x201F8EE2  （alpha 0x20）
state= 4 device   描边基色原值 0x2027C684  （alpha 0x20）
state= 5 ammoaid  描边基色原值 0x4027C684  （alpha 0x40）
state= 6 note     描边基色原值 0x221F8EE2  （alpha 0x22）
state= 7 resource 描边基色原值 0x00000000  -> alpha=0 已补 0xFF
state= 9 container描边基色原值 0x01FFAA00  （alpha 0x01）
state=10 door     描边基色原值 0x1EFF0000  （alpha 0x1E）
```

⇒ 两类「完全覆盖」的来源就清楚了：

1. **被补成 0xFF 的**（武器 state 0、防具 state 1）——引擎原本的基色 alpha 是 0
   （这两格从来没被初始化过），v4.19 为了让颜色画得出来补成不透明；
2. **脉冲色** —— 三处里脉冲 High 的 alpha 实测大多是 `0xFF`（引擎的脉冲动画本来就
   在 FF↔80 之间呼吸），我们只换 RGB 保留它 ⇒ 脉冲相位上仍是接近不透明的覆盖。

而"粉红手枪"（截图里 `#FF2E2E` 的红显示成粉红）说明**渲染确实做了混合，不是纯色平涂**
——颜色被材质/光照调制过。所以「用 alpha 调整覆盖强度」是对症的。

## 二、v4.20 的改动

| # | 改动 | 说明 |
| --- | --- | --- |
| ① | `Config` 新增 `colorAlpha[12]`（`std::uint8_t`，**0 = 特殊值 = 保留引擎原值**） | 0 必须能表达「别动 alpha」（= v4.19 行为），这样**没被点名的类别与 1.7.1 逐字节一致** |
| ② | 默认值：`weapon / apparel / door = 102`（≈40%），其余 = 0 | 只动用户点名的三类 |
| ③ | INI 新键 `AlphaLoot / AlphaWeapon / AlphaApparel / AlphaAmmoAid / AlphaNote / AlphaResource / AlphaContainer / AlphaDevice / AlphaDoor / AlphaFlora / AlphaOther / AlphaCorpse`（十进制 0~255） | 不写也生效（默认在 DLL 里）；改完重进游戏即可，不用换 DLL |
| ④ | `WriteColorOverrides`：三处（High / Low / 基色）**统一** `alpha != 0 ? (alpha<<24)\|rgb : (原 alpha)\|rgb`；基色保留「alpha 仍为 0 时补 0xFF」的兜底 | 渲染器到底消费哪一处无法离线确认（渲染侧 32 字节参数块的基色与脉冲色**都带 alpha**）⇒ 三处同值最稳 |
| ⑤ | 同状态「颜色相同但透明度不同」也打 WARN（限流） | 共享 state 的两组（容器+尸体、弹药+植物）如果透明度不一致，会互相覆盖 |
| ⑥ | 日志补 alpha：`config: colorAlpha ...`、`outline colors[...]` 与 `renderer params[...]` 的 **`a=XX`** 列 | `renderer params` 的 `a=` = **渲染器实际拿到的透明度** ⇒ alpha 有没有生效一眼可看 |
| ⑦ | 版本：DLL `4.19.0` → **`4.20.0`**；MO2 / N 网公开版 `1.7.1` → **`1.7.2`** | `tools/build-sas.ps1` 的 `meta.ini` 同步 |

### 为什么不直接"把颜色调暗"

用户要的是"**看得见物品本身**"，不是"颜色更暗"：调暗颜色属于「换一套更灰的色」，
材质该被盖住还是被盖住（不透明覆盖与亮度无关）。**alpha 才是"让材质透出来"的唯一参数**，
所以本轮只动 alpha（单一变量，便于用户判断是否有效）。

### 风险与备选（如实记录）

* **alpha 是否真的被渲染消费，尚未反汇编证实**。间接证据有两条：
  ① 引擎给脉冲色预设了 High `0xFF` / Low `0x80` 两端（静态初始化函数），
     这正是"呼吸"用的透明度动画；
  ② 用户截图里 `#FF2E2E` 的红以粉红呈现 ⇒ 渲染不是纯色平涂，存在混合。
  **验证手段**：v4.20 的 `renderer params[...] … 基色=#RRGGBB a=XX` ——
  若该 `a=` 等于配置值（如 `66`），说明 alpha 至少已经进了渲染侧参数块。
* **若实测确认 alpha 无效**（`a=` 对但画面不变），下一步方向：
  ① 调暗这三类的颜色（`ColorXxx`，例如白 `#FFFFFF` → 灰白）；
  ② 反汇编渲染侧对参数块的消费路径，找真正的混合参数（32 B 块里的 `+0x0C`/`+0x10` 两个 float）。

## 三、验收点（下一次进游戏）

1. 启动日志出现：
   ```
   config: colorAlpha（覆盖不透明度，0=保留引擎原值，255=不透明）: weapon=102 (40%), apparel=102 (40%), door=102 (40%)
   ```
2. `outline colors[install]` 的覆盖行末尾带不透明度，且
   **state 0 / 1 / 10 的 `基色` 与 `脉冲High/Low` 三列 `a=` 都应是 `66`**：
   ```
   outline colors: state=0 覆盖为 #FF2E2E <- weapon（描边基色原值 0x003EADF2，alpha=0 已补 0xFF；脉冲 High 原值 0xFF3EADF2；不透明度 102/255（约 40%））
   ```
3. ★ `renderer params[...] … 基色=#FF2E2E a=66 脉冲=#FF2E2E a=66`（武器）——
   这是"alpha 有没有送到渲染器"的直接证据。
4. ★★ 肉眼（本轮核心）：走到门前 / 看地上的武器和宇航服 ——
   **能看清物品本身的材质与轮廓**，同时红 / 品红 / 白仍然一眼可辨；
   其余类别（弹药亮绿 / 笔记黄 / 资源紫 / 容器橙 / 设备青 / 杂项蓝）**观感与 1.7.1 完全一致**。
5. 不回归：F8 / 扫描仪自愈（用完扫描仪 1 秒内重挂且颜色/透明度仍是新的）/
   展示柜拿空熄灭 / 换场景不崩 / 活人一个都不亮。
6. 觉得还是太深或太浅 ⇒ 只改 INI（`AlphaWeapon=77` ≈30%、`51` ≈20%、`255` = 不透明、
   `0` = 回到 1.7.1 的引擎原值），重进游戏即可。

## 五、可复用经验

1. **「颜色覆盖强度」只有一条正确的路：alpha**。亮度/饱和度只是换颜色，改不了
   "盖不盖得住材质"；而引擎本来就把 alpha 写进了这套配色（原版脉冲 High `0xFF` /
   Low `0x80` 就是呼吸动画），所以它一定是有语义的。
2. **特殊值要留"不动"这一档**：`AlphaXxx=0 = 保留引擎原值`，让「没被点名的类别」
   与上一版**逐字节相同** —— 需求只点名三类时，不做任何无谓改动是最稳的（避免把
   已经验收过的观感改坏）。
3. **一个参数要同时写进"所有可能被消费的地方"**：渲染侧参数块里基色与脉冲色都带
   alpha，无法离线判定谁被消费 ⇒ 三处（High / Low / 基色）写同一个值，并且把
   **渲染侧收到的 alpha 打进日志**（`renderer params … a=`），把"不确定"变成"可观测"。
4. **用户描述的"深/浅"要落到具体参数上**：本轮把「覆盖太深」翻译成
   「三处 alpha 中的 FF / 补出来的 FF」，再翻译成「INI 可调的 0~255」，
   用户从此可以自己微调（不用每次等作者编译）。
