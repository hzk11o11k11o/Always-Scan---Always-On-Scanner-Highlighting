## 零、一句话结论

「信用条」**不是** MISC 的 `Credits`（它的中文名是**信用币**），而是 **3 条 FLOR 记录**
（`Loot_CredStick_Small / _Common / _Rare`）。而 `ClassifyBase()` 把所有 **FLOR** 一律归到
「植物 / 星球目标」（走已扫描 / 未扫描判据、画**青色脉冲** = state 7）—— 所以 2.0.1 新增的
「黄组」**天然不可能**命中它，用户看到的青色正是这条路径的产物。

修法一句话：`ClassifyBase()` 的 `kFLOR` 分支**先**按 FormID 认这 3 条，命中即归「黄组」。

## 一、取证链（四步，全部可复跑）

### ① 中文名对照：`Credits` ≠ 「信用条」

| 记录 | 签名 / FormID | zhhans 名（FULL → 字符串表） |
| --- | --- | --- |
| `Digipick` | MISC 0x0000000A | 撬锁器（FULL = 0x00000ECC） |
| `Credits` | MISC 0x0000000F | **信用币**（FULL = 0x00000ED8） |
| **`Loot_CredStick_Small`** | **FLOR 0x003CC32C** | **信用条**（FULL = 0x0002E65E） |
| **`Loot_CredStick_Common`** | **FLOR 0x003CC325** | **信用条**（FULL = 0x0002E660） |
| **`Loot_CredStick_Rare`** | **FLOR 0x003CC32A** | **信用条**（FULL = 0x0002E662） |

★ 第一轮做「黄组」时按 EDID 的 `digipick|credit` 检索 MISC，命中的是上面两条 MISC
（`Credits` = 信用币）——**名字差一个字，记录完全是另一条**，这就是本轮的坑。

### ② 从本地化 BA2 里抽出中文串表，grep「信用条」

```powershell
python tools/re/ba2list.py "D:\SteamLibrary\steamapps\common\Starfield\Data\Starfield - Localization.ba2" `
    --grep zhhans --extract out\loc_ba2
python tools/re/ststrings.py dump out\loc_ba2\strings\starfield_zhhans.strings --grep 信用条
# → 0002E65E / 0002E660 / 0002E662  三个字符串 ID，文本都是「信用条」
```

### ③ 全量扫 ESM，按 `FULL` 反查这三个字符串 ID

```powershell

# → 3 条命中，全部是 FLOR：
#   FLOR 0x003CC325 Loot_CredStick_Common

# → 正好就这 3 条；KWDA 为空 ⇒ 没有关键词可用，只能按 FormID 判
#   （MODEL = Landscape\Flora\Flora02.nif，PFIG = 0x2EDE6B/6C/6D）
```

## 四、验收判据

1. ★ 核心：走到桌前，**「信用条」小卡片 = 黄色**（#FFE100），不再是青蓝色；
2. 统计行 `category (本轮选中): … pickcredit=N`（N ≥ 1）—— 以前整局恒为 0；
3. 日志（本机开发版）出现一次 `pickcredit: 首个黄组命中 base=0x3CC32x（信用条 Loot_CredStick_*）`；
4. 拿起来 / 拿走后不再被当成植物：**不再**出现 `flora scan: base=0x3CC32x`；
5. 不回归：开锁器 / 信用币仍黄、植物 / 矿脉仍是青↔绿、门品红、设备原版绿、杂项蓝、
   容器 / 尸体橙、活人一个都不亮、F8 开关正常。

## 五、经验

- **「名字 ≠ 记录」**：中文名只差一个字（信用币 / 信用条）就是两条完全不同的记录 ——
  用户报「某某没变色」时，第一步应该是**把那个名字换成字符串 ID，再反查记录**，而不是
  去猜它属于哪个已有类别。
- **同一件东西在游戏数据里可能跨签名**：`Digipick` / `Credits` 是 MISC，而地上的「信用条」
  是 FLOR（散落物形态）。写死 FormID 的判据必须**在每个可能的分支里**都认一遍
  （本轮就是 MISC 分支认了、FLOR 分支没有）。
- **类别即命运**：任何一类被归进「植物 / 星球目标」，就必然背上 state 7 的青色与
  已扫描 / 未扫描判据 —— 排查「没有变成想要的颜色」时，先看日志里它落在哪个类别，
  比看颜色代码更快（本轮 `状态 7（未扫描青）` 一行就定了案）。
